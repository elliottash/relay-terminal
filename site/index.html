Beta · Linux

A Linux terminal with its own engine and bring‑your‑own‑key agents

Relay runs its own terminal engine and puts a single prompt box under it. Type a shell command or ask for something in plain language; Relay works out where the line goes. The agent runs on your own API key, and its commands, diffs and answers print in the terminal.

Build it Source on GitHub

What it does

  • Its own terminal engine

    Relay renders the terminal itself — libghostty-vt, or a patched libvterm, behind one emulator interface. It is the default and is chosen per pane, so KonsolePart is still there under --engine=konsole. Shell integration (OSC 7 and OSC 133) tracks the working directory and marks prompts, commands and exit codes.

  • The prompt box is the only input

    Clicking the terminal selects text, scrolls and follows links; it never takes the keyboard. Full-screen programs such as vim, less and ssh offer Take control (Ctrl+H) instead of grabbing it.

  • Passwords stay in the box

    When a program turns echo off, the prompt box becomes a masked field and writes the line straight to that program. The text never enters prompt history, the queue, session files, logs or any model prompt, and it is wiped as soon as it is sent.

  • Command or request, decided locally

    git status runs in the shell; why is this build failing? goes to the agent. Type ! or * to force one line, Ctrl+I to cycle auto → terminal → agent. The caret and the syntax colouring show where the line is going before you press Enter.

  • Nothing is silently dropped

    Every request you make is tracked, and multi-part asks are split into tasks. A chip counts them — Tasks 3/5 (1 deferred, 1 failed) — and the list shows your words next to what the agent actually did.

  • Search what you have already done

    Ctrl+Shift+O searches every saved conversation and Relay's terminal history: prompts, answers, tool calls, the commands Relay ran and their output. Ctrl+F searches the pane in front of you. The index is a local SQLite file.

  • One provider choice, three models

    Pick a default provider and Relay derives Main, Flash and Lite models from it for agent turns, quick side calls and labels. Bring your own key for GLM, Kimi, Kimi Code, MiniMax, OpenRouter, OpenAI, Anthropic or Gemini; the API keys window has a Test button and keeps keys in your system keyring.

  • Reopen where you left off

    Quit and start again: windows, tabs and panes come back in their directories, on the same models, with their conversations reattached. The shells are new; nothing is re-run.

  • The Switchboard (in progress)

    Cards, plans and memory live as Markdown in git next to the code, so the agent and you read the same tracker. The card format, the append-only threads and the relay-board checker are in; the pane inside Relay is the next piece.

  • Dictate a prompt

    Hold Right Alt, or click the microphone chip, and Relay records with whatever capture tool your desktop has. The transcript (an OpenRouter key does the work) is inserted at the cursor and never submitted for you.

  • Panes, tabs and the keyboard

    Each pane has its own shell, prompt and conversation. Move panes by dragging the grip or with Ctrl+Alt+arrows, open folders and file previews beside the terminal, and drive everything from the actions palette. Keymap presets for Relay, Warp, VS Code and Konsole; Ctrl+? lists every shortcut.

  • Yours, and only yours

    No telemetry, no analytics, no crash reporting, no account and no Relay server. Relay reaches the network only to talk to the provider you configured. GPL-3.0-or-later.

Install

No packaged build yet. The beta .debs and AUR packages are prepared but not published, so there is nothing to download from Releases today. Build from source with the recipes below; this section will point at the beta build as soon as it is out.

Ubuntu 24.04 LTS (Qt 5 / KF 5)

The Konsole part and the two optional viewers can be left out.

sudo apt install build-essential cmake ninja-build python3 \
  libsecret-tools qtbase5-dev libkf5parts-dev libkf5coreaddons-dev \
  libkf5syntaxhighlighting-dev qtpdf5-dev
# only if you want the Konsole engine:
sudo apt install konsole-kpart

Debian 13 or Ubuntu 26.04 (Qt 6 / KF 6)

Same shape, KDE Frameworks 6 package names.

sudo apt install build-essential cmake ninja-build python3 \
  libsecret-tools qt6-base-dev libkf6parts-dev libkf6coreaddons-dev \
  libkf6syntaxhighlighting-dev
# only if you want the Konsole engine:
sudo apt install konsole-kpart

Build and run

build.sh configures, builds and runs the tests.

git clone https://github.com/elliottash/relay-terminal
cd relay-terminal
./scripts/build.sh
./build/relay --workspace ~/project
cmake --install build      # optional, installs to ~/.local

What it needs

CMake 3.22+, a C++17 compiler, Qt with KDE Frameworks Parts and CoreAddons, Python 3.10+ and Bash. Relay picks Qt 6 + KF 6 when both are installed and falls back to Qt 5 + KF 5; force one with ./scripts/build.sh -DRELAY_QT_MAJOR=5. Syntax highlighting and PDF preview are optional, and konsole-kpart is only needed for --engine=konsole.

Choosing an engine

Relay's engine is the default and is built into every build. The libvterm core needs nothing extra; the libghostty-vt core is optional and needs Zig to build.

relay                      # Relay's engine
relay --engine=konsole     # KonsolePart instead
relay --engine-core=libvterm   # pick the emulator core

Keys

Add a provider key in Settings › Models › API keys… (Ctrl+,). Keys go to the desktop keyring through secret-tool — install libsecret-tools on Debian/Ubuntu or libsecret on Arch — or come from an environment variable such as RELAY_OPENROUTER_API_KEY.

Start Relay from your application menu or run relay --workspace ~/project. --fresh skips the saved window layout once, and --clean-shell skips ~/.bashrc for prompt plugins that clash with Relay's shell hooks.

Your key, your provider

What stays with you

  • No telemetry, no analytics, no crash reporting.
  • No Relay account and no Relay server. Relay connects to the network only to reach the provider you configure, when you use the agent.
  • API keys live in your desktop keyring (GNOME Keyring or KWallet, through secret-tool) or in an environment variable. They are passed on stdin, never on a command line, in a settings file or in a log.
  • Shell commands you run stay on your machine, and terminal output is never sent on its own.
  • A password typed at a masked prompt goes to that program and nowhere else — not to history, the session file, the logs or any model.
  • Conversations and their search index are files on your disk, deleted with the conversation.

What goes to your provider

  • Your agent prompts, the conversation, and the results of the agent's tools (command output, file contents it reads) go to the provider you configured: GLM, Kimi, MiniMax, OpenRouter, OpenAI, Anthropic, Gemini or any other OpenAI-compatible endpoint. Their privacy policy applies.
  • Agent tools run without asking for approval. The agent can run commands and write files in your workspace as your user. Shell commands are not sandboxed; file tools stay inside the workspace. Every action prints in the terminal and you can stop the agent at any time, but nothing is rolled back. Start with a project you can afford to break.

Status

Beta, and not independently tested yet. Relay is usable day to day on Linux, but expect rough edges and changes between releases. Please report problems on GitHub Issues.

Each pane runs Bash. The shell-integration script that feeds Relay the working directory and the prompt marks ships for Bash and Zsh and is opt-in; without it the terminal still works, with fewer marks.

Platforms. Linux, built against Qt 6 + KDE Frameworks 6 or Qt 5 + KF 5. Relay's own engine is the step towards macOS and Windows; those builds also need the rest of the app off KDE Frameworks, and are on the roadmap rather than in this beta.

License. GPL-3.0-or-later. Relay is not a Konsole fork and changes no Konsole settings; it can load Konsole's part, as installed on your system, as an alternative engine. No Warp or other proprietary code is included.
