Research note (from model knowledge, not a live web search — a Discuss pane cannot browse; Run can do the live search if wanted):

**Warp sidebar tabs reception:** Warp itself ships horizontal tabs only; its left sidebar is the file tree / Warp Drive, not tabs. Vertical tabs are a long-standing upvoted request in warpdotdev/Warp's issue tracker. Sentiment pattern: users who keep many sessions open want them; users with 2-4 tabs see them as wasted horizontal space — which argues for vertical as an *option*, not a forced default.

**Apps to learn from:**
- **Arc browser** — the strongest proof vertical tabs work: tabs + bookmarks in one left sidebar, titles readable, collapsible. Widely loved; the main complaint is relearning muscle memory.
- **Edge / Brave vertical tabs** — well received by heavy tab users; both keep horizontal as an option and remember the choice per window.
- **Firefox + Tree Style Tab / Sidebery** — devoted niche; shows power users want hierarchy and metadata (unread, activity) in the list, not just rotated tabs.
- **Zellij** — terminal multiplexer with a session/pane list; closest terminal analogue for showing per-tab metadata (cwd, running command).
- **Windows Terminal** — vertical tabs repeatedly requested, never shipped; the requests emphasize wide terminals make horizontal tabs unreadable past ~6 tabs.

**Design takeaways for us:** (1) make it a runtime setting, horizontal stays default until proven; (2) a vertical tab list should show title + directory + pane count (Warp-style), not rotated text — matches the card's existing note that QTabWidget west tabs are not enough; (3) identical shortcuts in both layouts; (4) auto-collapse/width like Arc is a nice-to-have later.
