Started (claude-opus-5-5 via claude-code, land session `2fq9`). Design from reading the code:
- **Pane (w0):** a console already has a vterm backend (the transcript), and only the pty is skipped (`startTerminal`'s early return). Pop-out starts a pty **on that same backend** (new `Pane::setLinkedShell`, src/PaneLinkedShell.cpp). The console keeps the tab worker, so no second worker starts. `startTerminal` is left alone, because other sessions have uncommitted hunks in it. The engine gets two small changes: `TerminalBackend::stopProgram()`, and a `TerminalSession` that may start again once its program has ended. Without the second, dock → pop out again would fail.
- **Routing:** while linked, a `!`-prefixed line or Terminal mode on the mode chip goes to the pty. Every other line and chord (Enter / Ctrl+Enter / Ctrl+Shift+Enter) still goes through `Context::submit`, so a card's `board_ask` and its thread provenance do not change.
- **Window (mx):** this works for any host. A placeholder ("agent is in the linked pane · Dock back") takes the console's slot in the host's layout, and the console moves into a new `ToolPane::Kind::LinkedAgent` leaf beside the host. Docking reverses that and stops the pty. Closing the linked leaf docks back, and so does typing `exit` in its shell. Closing the host closes the linked leaf too: the host owns the context, so the agent cannot outlive it. The conversation is the worker's persisted (tab, card/file) one and returns when the artifact reopens.
- **Restore (rp):** the host leaf saves `agent_linked: true`. The linked leaf saves nothing, and on restore the host pops its agent out again.
- **Entry points (k3):** "⤴ Agent + shell" beside the card page's existing "⤴ Own pane", which stays separate; ⤴ beside fold in the file agent's head row; and a palette action `agent.linkShell` with no default key.
