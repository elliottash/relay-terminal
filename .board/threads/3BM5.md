Lessons for the dev system:
1. A land claim should be tied to the pane that holds it. Board claims are released when the pane closes; land.py claims are not. There are 750 sessions in /tmp and ~150 stale, so `who` stays noisy. land.py should record the pane token and expire the claim when the pane goes away.

Two more lessons from tonight's #R5TC salvage, both about picking hunks out of a file several cards share.

7. **Hunk numbers are position, not content.** The Security › "Unattended turns get the full tool set" row was silently missed by 2e6ad863: its selection had been numbered with one diff context (`-U1`) while `commit` numbers with another (`-U3`), so the wrong hunk was excluded and the commit message described a row that never landed. a2 caught it; landed as 8e5606ef. Fix worth building: content-addressed selection (`--only-hunk <path>:<anchor text>`), so a selection survives renumbering — and never hand-number hunks outside land.py.

8. **One hunk can carry two cards.** The palette hunk held #R5TC's "Message another pane…" and #XQ8F's remote-pane entries together, so neither session could land its card whole; it waited until both sides were on main and landed alone (16763f52). When a shared hunk is found, the card needs a hand-off note naming the other card, or land.py needs to let one commit carry a second card's tag.
