- `JobTable.start()` (backend/relay_core/jobs.py:107-109) deletes the oldest finished jobs once more than KEEP_FINISHED=16 finished jobs are remembered. job-10 was pruned silently at a later `start()`.
- Message 66: `command_output('job-10')` → `{"error": "No command 'job-10'. Job ids come from a run_command result (\"job_id\"); jobs end with the conversation."}` (jobs.py:121-123).

So not a crash and not a wrong refusal: the job existed, finished, and was forgotten by design. The problems: (1) the error text claims the only ways a job id can be invalid are a made-up id or a conversation end, never mentioning pruning, so model and user both misread it; (2) a handed-back job the model never read after it finished (read_pos < total) can be dropped with its unread output; (3) the hand-back note ("Read more with command_output") gives no hint the job only survives ~16 further commands; (4) a pruned job also vanishes from the user's JobsPanel without a trace.

Options: tombstone forgotten ids so the error can say "job-10 finished and was forgotten (only the last 16 finished jobs are kept)"; don't prune finished jobs with unread output (bound with KEEP_BYTES, or raise KEEP_FINISHED); reword the generic error to name pruning.
