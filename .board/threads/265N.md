what harness is relay-vterm-spike

<!-- relay:entry 20260925T221252Z-hr author=agent kind=comment mode=discuss model=glm-5.3 turn=8b74b2bb1980ca5677b32b2d0aa850e1/bcd6b7eb354a451288c48205c4b572eb -->
`relay-vterm-spike` is a small standalone window, not a test runner — a one-terminal debug app for the engine.

- Built from `engine/main.cpp` only when `-DRELAY_BUILD_ENGINE=ON`: it opens a single `QApplication` window running `VTermBackend` (core selectable with `--core ghostty|libvterm`), with flags for `--size`, `--font`, `--cwd`, `-e PROGRAM`, `--folds`, and `--dump FILE` (Ctrl+Shift+D appends a full screen-state dump).
- It exists so you can exercise the terminal engine — rendering, folds, links, alt-screen, callbacks (logged to stderr) — without booting all of Relay. The automated engine tests are separate targets (`relay-engine-tests`, `relay-engine-bench`); the spike is the manual half.
- "Harness" in the plan means the xdotool side: `engine/scripts/gui/{folds,perf-cat,scenarios}.sh` drive its window by typing into it, and past QA evidence under `docs/qa_evidence/` names the binary. That's why `docs/ENGINE.md:53` says the name was kept — renaming it breaks those scripts and the recorded evidence commands, which is Q1's recommendation to keep the name and drop only the deprecated `RELAY_BUILD_ENGINE_SPIKE` CMake alias.
