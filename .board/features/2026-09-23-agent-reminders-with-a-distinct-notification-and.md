# Agent reminders with a distinct notification and audible bell

## Issue
add a reminder tool to relay, it will show a special notification and play a bell

## Done means
A Relay agent, including a guest agent, can set, list, and cancel a reminder with a clear due time. Pending reminders survive an agent restart and a Relay restart. A due reminder appears as a distinct in-app reminder notification, raises a desktop alert, and sounds a bell once; invalid or past times are refused.

## Plan
**Goal.** Give every Relay-managed agent one `app_reminder` tool for set/list/cancel and deliver due reminders through Relay’s notification center with an audible bell.

**Findings.** `backend/relay_core/app_tools.py` owns the stable app tool list and uses `app_command` to ask the GUI; `src/AppCommands.cpp` executes those commands. `src/Notifications.h` and `src/WindowChrome.h` draw in-app entries; `src/Pane.h::notify` sends ordinary desktop alerts only while unfocused. The app has no reminder store or scheduler.

**Steps.** 1. Add one validated tool that accepts an ISO time with timezone or a relative minute delay, plus list/cancel by returned ID; the guest bridge inherits app tools. 2. Add a GUI-owned persistent store and timer, loaded at startup; mark a due reminder delivered before alerting so restarts do not repeat it. 3. Add reminder-specific notification style, an always-visible desktop alert when due, and `QApplication::beep()`. 4. Update the GUI↔worker protocol and targeted tests; capture an isolated-profile notification.

**Risks.** A machine asleep or Relay closed at the due time receives the alert on the next Relay launch. Native bell audibility depends on the OS sound configuration. Multiple simultaneous Relay processes must not fire the same reminder twice; the persistent store needs a lock or a single-instance claim.

**Verify.** Set/list/cancel validation, due-once and restart behavior, one notification with reminder styling, and one bell call in a headless Qt test. Build with `scripts/relay-build` and capture a GUI screenshot.

## Execution Summary
Implemented one `app_reminder` tool for native and guest agents, with set/list/cancel actions, timezone-aware due times, and worker-side validation. The GUI stores reminders atomically with a file lock; it claims a due reminder before alerting and checks overdue reminders on launch. A due item posts a distinct amber reminder entry, requests a desktop alert when enabled, and plays the Linux desktop bell (or Qt system bell fallback). `app_reminder` is in Relay's deferred app tool group, preserving the existing token-efficient tool-list order. Protocol section 30 documents the command.

Built `relay` and targeted Qt tests; 84 app-tool Python tests and three Qt test targets passed. The isolated-profile screenshot below is generated by a scheduled due reminder through the real reminder store and popup. Audibility on the user's desktop still needs human verification.
