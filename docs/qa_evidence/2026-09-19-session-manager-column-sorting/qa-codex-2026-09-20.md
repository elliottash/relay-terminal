## Verdicts, per the card's QA checklist

- **Backend orders — PASS.** The implementer's exact test selection passes
  (`IndexTests.test_shortest_title_and_model_sorts`, `ThreadStoreTests.test_sort_and_paging`), and
  the tests assert all five new ids' ordering, NOCASE titles with ties broken newest first, a
  rename re-keying the row, the Model CASE mirroring the column text (a terminal row sorts as
  "terminal", between "m" and "zeta"), pinned first in every order, and `ValueError` on an
  unknown sort. `conv_index.py` matches: `SORTS` (line 194) gains the five ids, `_TITLE_KEY` /
  `_MODEL_KEY` (201–203) mirror the GUI's column text, the `order` map (1746–1755) breaks every
  tie `COALESCE(c.updated, 0) DESC`, and both query branches order by `c.pinned DESC, {order}`.
- **Header clicks — PASS.** `headerClickSortsByThatColumn` passes offscreen and asserts the real
  chain: `sectionClicked(1)` sends `sort=oldest` and toggles back to recent (no `sort` field —
  recent is the default), `sectionClicked(0)` sends `title`, the Sort combo follows via
  `currentData()`, the header indicator's section and order follow each click, `relevance` hides
  the indicator, and Turns/Model clicks send `longest`/`model`. The combo lists all nine orders
  (`Conversations.cpp:600–608`), so it never names an order the list is not in.
- **The click is the user's own sort — PASS.** The same test asserts that after
  `sectionClicked(0)`, typing "pelican" still queries `sort=title` with the arrow on column 0;
  and that with no sort chosen, typing switches recent↔relevance with the arrow following
  (shown for `relevance`, hidden… shown again when the box empties). Source agrees: the header
  click goes through `m_sort->setCurrentIndex` (`Conversations.cpp:880–885`), so the combo's own
  `currentIndexChanged` wiring sets `m_sortChosen` (875–876) and the list's own recent↔relevance
  switches happen under a `QSignalBlocker` with `updateSortIndicator()` called by hand (857–864).
- **Tree shape survives — PASS.** `setSortingEnabled(false)` is the only sorting-enabled call
  (`Conversations.cpp:659`, with the comment saying why); no `sortItems`/`sortChildren`/
  `sortByColumn` anywhere in the file. `rebuildTree()` adds the Continue band first (1261),
  walks date groups in `dateGroupOrder()` (Today→Older), places session rows in worker order,
  and `stable_sort`s threads by `created` under their owner — nothing is reordered client-side.
  The existing shape tests (`groupingByDateAndTheContinueSection`,
  `subagentThreadsHangUnderTheirOwner`) passed in the same offscreen run.
- **Paging — PASS.** `test_sort_and_paging` asserts the five new orders end to end *with*
  `limit`/`offset` paging (`next_offset` present then absent, last page correct). "Show more"
  appends the next page client-side (`Conversations.cpp:1058`) while `queryRequest()` keeps
  sending the chosen sort, so the page continues in the clicked order. (Live click-through not
  observed — see the sweep.)
- **Live sweep — PARTIAL.** Under Xvfb with an isolated HOME/XDG (drive.sh pattern) the pane
  opened with 103 seeded sessions (written with the tests' own `session()` fixture into
  `$XDG_DATA_HOME/relay/sessions/<digest>/`, picked up by the worker's `reconcile()`), and the
  default listing matched the worker's `recent` order exactly — expected `007 030 053 076 099
  019 042 065 088 008`, OCR of the Session column read `030 053 076 099 019 042 065 088 008`
  with `007` sitting in the Continue band above (its place by design). But my synthetic xdotool
  clicks on the tree header did not register: after each "click" the screenshot — header arrow
  included — was pixel-identical (AE=0), so I could not observe the reorder/arrow/paging live
  and did not fabricate it. The whole click chain (click → sort id → combo → arrow → typing
  keeps it) is covered against the real widgets by `headerClickSortsByThatColumn`.

**Overall verdict: PASS** — every functional claim of the card is verified by the named tests
plus source reading; the one thing this verifier could not settle by hand (live header clicks
under Xvfb) is exactly what the offscreen test drives through the real widgets.
