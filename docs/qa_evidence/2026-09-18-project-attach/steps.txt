A tab is attached to a project, and starts attached to none (card #JN7X, stage 1)
================================================================================

Implementer evidence, not a QA verdict. Run live under Xvfb with a fully isolated
profile (HOME, XDG_CONFIG_HOME, XDG_DATA_HOME, XDG_RUNTIME_DIR and TMPDIR all
under one scratch directory) and RELAY_KEYRING=off, by

    docs/qa_evidence/2026-09-18-project-attach/drive.sh <build-dir>

Binary: a scratch build of the working tree (libvterm engine core; only that core
builds on this machine). **Relay was launched from this repository**, which has a
Switchboard of its own — exactly the trap the card is about: under the old rule
every pane in every window found *this* repo's board, wherever its terminal was.

The model is `stub-provider.py` on 127.0.0.1. It answers every turn "Done." and
appends one line per request to implementer-tools.log holding the tool names and
whether the system prompt carried a Switchboard block. That is how "the agent has
no board tools before the attach and has them after, in the same conversation" is
checked without a provider account: the `messages=` count is the conversation's
length, so a turn that grew it was not a new chat.

Fixture (in the sandbox, so nothing here is a real project):

    scratch/downloads   a plain directory: no board, no .git, nothing above it
    scratch/proj-new    .git + switchboard/board.yaml + card #NEW1   (new folder name)
    scratch/proj-old    .git + issues/board.yaml      + card #OLD1   (older folder name)
    scratch/proj-none   .git and nothing else         (a project with no board yet)

5. Quit and relaunch: the tabs come back attached
--------------------------------------------------
    SIGTERM (an ordinary quit: the layout is saved), then relaunch.

    The saved layout, read back out of state/windows.json:
        window 0 tab 0 project=…/scratch/proj-new  shape=wrapper
        window 0 tab 1 project=…/scratch/proj-old  shape=wrapper
        window 0 tab 2 project=(unattached)        shape=bare node
    An attached tab is `{"project", "node"}`; an unattached one is the bare node
    every earlier Relay wrote, so the file's schema version did not move.

implementer-09-restored-attached.png
    Both Switchboards are back in their own tabs ("Done; Switchboard · 1 open",
    "proj-old; Switchboard · 1 open"), the third tab is the plain proj-none one.

implementer-10-palette-no-detach-when-unattached.png
    On that third, unattached tab the palette search "Detach this tab" finds
    nothing: the quiet state does not advertise itself.

implementer-11-restored-tab-is-attached.png,
implementer-12-restored-tools-are-back.png
    Back on tab 1. "Session loaded: "Done" · 2 turn(s)" — the conversation from

    so the restored tab was attached before its pane's first configure.
