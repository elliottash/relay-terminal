# #HKAP — "Executing (<pane id>)" thread entry that jumps to the pane

Implemented 2026-09-20 by Relay's main agent (Claude Code, opus).

## What changed

- `BoardView::onExecuteCard` now returns the new pane's session token
  (`src/BoardPane.h`, `src/RelayWindow.h`); `executeCard` (`src/BoardPane.cpp`)
  opens the pane first and sends `board_comment {kind: "progress", pane_token,
  text: "Executing (<token left 8>) · handed to a new terminal pane beside the
  Switchboard, …"}` — keeping today's `Execute · …` wording when no pane opened.
- Worker: the GUI handler forwards `pane_token`
  (`backend/relay_core/board_protocol.py`), `board_comment` accepts it
  (≤64 chars, no whitespace or `>`) and `Board.append_thread` persists it as an
  entry attr (`backend/relay_core/board_tools.py`).
- GUI: a thread entry whose attrs carry `pane_token` draws its first line as a
  `relay-pane:<token>` anchor in the palette's link colour; clicking it goes
  `CardDetail::onFocusPane → BoardView::onFocusPane →
  WindowManager::focusPane(token)`, which reveals the pane in whatever window
  it lives in and no-ops when no pane has the token.
- `docs/AGENT-SESSIONS-PROTOCOL.md`: §19.10 Execute step order and wording, and
  `pane_token?` on the `board_comment` schema row.
- Verify's hand-off entry was left alone: the plan asked and the owner had not
  said the word when the card was executed.
