1. Does urlopen(timeout=N) cover each readline() on a streamed response?
================================================================================
Probe: two loopback servers, both sending SSE headers and then no answer; client timeout 2 s.

  /silent:    TimeoutError after 2.0s
  /keepalive: still reading after 8.0s, 79 keepalive lines, NO timeout
              — the socket timeout never fires

Answer: the timeout does apply to each read, but *any* byte resets it. A stream of SSE comments
or empty deltas is all bytes and no answer, so it never times out. That is how the observed
worker held an ESTABLISHED connection for 12+ minutes with an empty receive queue while the pane
showed only "thinking". Widening the timeout alone cannot fix that case; the deadline has to run
from the last *usable* chunk and be enforced by a watchdog that closes the response.
