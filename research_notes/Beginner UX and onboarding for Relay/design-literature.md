# Design Literature for a Dual-Audience Terminal+Agent (Relay)

Research notes: primary sources and well-documented case studies on the dual-audience problem (expert terminal users + terminal beginners) and on onboarding as a discipline. All quotes are verbatim from the cited sources; paraphrases are marked. Context: Relay is a desktop terminal that is also an AI agent workspace — one prompt box where shell commands run in the terminal and plain-language requests go to an agent, split panes, a project Board of task cards, and agents that can drive the terminal.

---

## 1. Foundational HCI: progressive disclosure, intermediates, affordances, modes, showing the data

**1.1 Progressive disclosure (Jakob Nielsen, NN/g).** "Progressive disclosure defers advanced or rarely used features to a secondary screen, making applications easier to learn and less error-prone." And: "Initially, show users only a few of the most important options and offer a larger set of specialized options upon request." The mechanism works because novices see only what they need and experts are one gesture away from the rest — it is *the* canonical answer to the two-audience problem. Source: Nielsen, "Progressive Disclosure," https://www.nngroup.com/articles/progressive-disclosure/

**1.2 Perpetual intermediates (Alan Cooper, *About Face*).** Cooper frames exactly Relay's problem as a "Conundrum: How to address the needs of both beginning users and expert users with a single, coherent interface?" His observation: "…everyone spends some minimum time as a beginner, nobody remains in that state for long…" and "Beginners improve to the intermediate level, but rarely become experts." Hence the design principles "Optimize for Intermediates" and, crucially, "Don't weld on training wheels" — onboarding affordances must not permanently clutter the expert interface. Sources: Cooper, Reimann, Cronin & Noessel, *About Face: The Essentials of Interaction Design* (Wiley), https://www.wiley.com/en-us/About+Face%3A+The+Essentials+of+Interaction+Design-p-9781118766576 ; chapter text: https://athena.ecs.csus.edu/~buckley/CSc238/Cooper_Ch10_F2016.pdf

**1.3 Affordances and signifiers (Don Norman).** Norman: "The real question is about the perceived affordance: Does the user perceive that clicking on that location is a meaningful, useful action to perform?" — perceived affordance, not capability, determines what users try. Source: Norman, "Affordances and Design," https://jnd.org/affordances-and-design/. In the revised *Design of Everyday Things* Norman sharpened this: affordances determine what actions are possible; signifiers communicate where the action should take place. A terminal prompt has capabilities but almost no signifiers — the agent box's job is to supply the signifiers the terminal lacks. See also the interaction-design.org topic page "Signifiers in User Design," https://www.interaction-design.org/literature/topics/signifiers-in-user-design, and Norman's gulf of execution (gap between the user's goal and the actions available) and gulf of evaluation (gap between system state and what the user can perceive) from *The Design of Everyday Things* (Basic Books, 1988/2013).

**1.4 Tognazzini's First Principles of Interaction Design.** Bruce "Tog" Tognazzini's first principles include: **Explorable Interfaces** (reduce the cost of mistakes so people can learn by exploring), **Protect Users' Work** (never lose work to error or failure), **Anticipation**, **Defaults**, **Efficiency of the User**, **Fitts's Law**, and **Latency Reduction**. Explorable interfaces and protecting work are the two principles a terminal most violates by default and an agent layer most easily fixes. Source: "First Principles of HCI Design" (asktog.com; original now offline, archived), https://web.archive.org/web/20140322100458/http://asktog.com/atc/category/human-computer-interaction-hci/hci-design/principles-of-hci-design/first-principles/

**1.5 Raskin: modes, habituation, and the humane command line (Jef Raskin, *The Humane Interface*).** "A mode is a state in which the computer produces a different output for the same input than it would have if it were another state; the classic example is the keyboard's caps lock key." Raskin "advocates either getting rid of them entirely or using 'quasimodes'… a state in which the user must make some constant physical action in order to keep the computer in that state, so that they cannot forget." And: "Habituation is an important concept driving Raskin's guidelines, intended to free the user's mind from attention to low-level interaction details." His vision (realized in the Canon Cat) was modeless, document-centered computing with one universal place to type commands — the intellectual ancestor of a unified shell+agent prompt box. Sources: *The Humane Interface* (Addison-Wesley, 2000); summary and quotes: https://en.wikipedia.org/wiki/The_Humane_Interface

**1.6 Bret Victor: see the execution; start somewhere, then sculpt.** In "Learnable Programming": "Programming is a way of thinking, not a rote skill. Learning about 'for' loops is not learning to program, any more than learning about pencils is learning to draw." And: "People understand what they can see. If a programmer cannot see what a program is doing, she can't understand it." The environment should let users "create by reacting — start somewhere, then sculpt," and "create by abstracting — start concrete, then generalize" — a direct argument that a blank prompt is hostile and that suggestions/previews are learning tools, not crutches. Source: http://worrydream.com/LearnableProgramming/. In "Magic Ink," Victor argues most software is *information software* whose ideal is to infer context and answer with well-designed graphics instead of demanding interaction ("Interactivity considered harmful"). For a hybrid command/agent box: the agent should answer with structured, contextual output (a Board card, a diff, a tree), not force users through question-after-question interaction. Source: http://worrydream.com/MagicInk/

**1.7 Shneiderman: direct manipulation and the visual-information mantra.** Ben Shneiderman's 1983 "Direct Manipulation: A Step Beyond Programming Languages" (IEEE Computer 16(8)) established that people learn faster and feel more in control with continuous visible representations, incremental reversible actions, and immediate feedback — the opposite of a line-mode terminal. His later mantra for information visualization: "Overview first, zoom and filter, then details on demand." Source: Shneiderman, "The Eyes Have It: A Task by Data Type Taxonomy for Information Visualizations" (1996), https://www.cs.umd.edu/~ben/papers/Shneiderman1996eyes.pdf. For Relay: the Board is the overview, a card is the zoom, the terminal transcript is details on demand.

## 2. Onboarding as a discipline

**2.1 Definition (Samuel Hulick, UserOnboard).** "User Onboarding is the process of radically increasing the likelihood that new users become successful when adopting your product." Hulick's site popularized the teardown of first-run flows as a method; the definition centers the user's success, not the product's features. Source: https://www.useronboard.com/

**2.2 Front-loaded tutorials fail; contextual help wins (NN/g).** Page Laubheimer's research summary: "Tutorials interrupt users, don't necessarily improve task performance, and are quickly forgotten. Contextual help signals can avoid these pitfalls but require unintrusive ways to activate." Source: NN/g, "Onboarding Tutorials vs. Contextual Help" (Feb 12, 2023), https://www.nngroup.com/articles/onboarding-tutorials/. Companion pieces: "Feature Checklists Are Not Enough" (Kathryn Whitenton, 2021) — a checklist of features is no substitute for task analysis and information delivered when needed, https://www.nngroup.com/articles/feature-checklists-are-not-enough/; and "Tooltip Guidelines," which constrain tooltips to hover/focus targets, brief text, and first-use relevance, https://www.nngroup.com/articles/tooltip-guidelines/.

**2.3 Aha moment and time-to-value (Appcues).** "A typical user onboarding journey moves through a few distinct stages: signup, initial setup, first key action, and the aha moment — the point where the user first experiences the core value your product delivers. The aha moment is the north star of onboarding design… Everything in your onboarding flow should be engineered to get users to that moment." The same guide documents two evidence-backed tactics: learn-by-doing (Grammarly's hotspots: "You learn how to use its features by using its features") and personalization ("One-size-fits-all onboarding consistently underperforms… Segmenting users by role, use case, company size, or stated goal allows you to deliver guidance that feels relevant rather than generic"). Source: Appcues, "User Onboarding," https://www.appcues.com/blog/user-onboarding/

**2.4 Activation metrics are behavioral, not clicks.** Slack's canonical metric: "In Slack's case, it's a team that hits the milestone of sending 2,000 messages — from there, the product fans outward in that team's organization to more and more employees." Source: Index Ventures, "Growing as Fast as Slack," https://www.indexventures.com/perspectives/growing-as-fast-as-slack/. Facebook's "7 friends in 10 days" rule is attributed to Chamath Palihapitiya's 2007-era growth team ("Led by Chamath Palihapitiya, the team was given a singular mandate to grow the number of users on the platform…" with a "data-driven approach"); a documented retelling: https://jamesmorrison.substack.com/p/2-facebooks-magic-number-7-friends. The generalizable lesson: find the single behavior that predicts retention and engineer the first session to produce it.

**2.5 Superhuman's onboarding playbook (First Round Review, Apr 2025).** "A human-led onboarding can push every new customer to make it through 'Signed up,' 'Setup Moment,' and 'Aha Moment.' If done well, it can set them up with 'Habit Moment,' and put them well on their way toward 'Engaged.'" And: "Over 65% of new customers fully transitioned their email to Superhuman after their human-led onboarding. This was more than double what we observed by simply dropping users into the product, absent any in-app onboarding, and letting them figure it out themselves." Their counterintuitive finding: "the most effective product onboardings embody three attributes that product and growth teams typically shy away from: opinionated, interruptive, and interactive." Source: https://review.firstround.com/superhuman-onboarding-playbook/. The earlier PMF article documents the keyboard-first bet: users say "keyboard shortcuts make me an actual superhuman," https://review.firstround.com/how-superhuman-built-an-engine-to-find-product-market-fit/

**2.6 Empty states are onboarding surface area (NN/g).** "Empty states provide opportunities for designers to communicate system status, increase learnability of the system, and deliver direct pathways for key tasks." Source: NN/g, "Empty-State Interface Design," https://www.nngroup.com/articles/empty-state-interface-design/

**2.7 Krug's laws and growth case-study libraries.** Steve Krug's *Don't Make Me Think* (3rd ed., New Riders, 2014) — first law: "Don't make me think"; third law: "Get rid of half the words on each page, then get rid of half of what's left." Book page: https://sensible.com/dont-make-me-think/. Growth.design's comic-format case studies apply behavioral psychology to real onboarding flows (e.g., "Duolingo's User Retention: 8 Tactics Tested on 300 Million Users," "3 UX Tips To Make 'Aha Moments' Click," "Labor Perception Bias: Why Faster Isn't Always Better"), https://growth.design/case-studies. Intercom's product-tour guidance boils down to targeting: "Send your product tours to the right people" (right user, right moment, one job per tour), https://www.intercom.com/help/en/articles/3095688-best-practices-for-using-product-tours.

## 3. Command palettes, linear interfaces, and hints that fade

**3.1 What a palette is (definition).** "A command palette is a searchable index of software commands, appearing as a modal palette window with a search box and suggestions list. It allows the user to recall and immediately invoke a command by name, using incremental search, fuzzy search, or a list of recently or frequently used commands." Source: Wikipedia, "Command palette," https://en.wikipedia.org/wiki/Command_palette. History: popularized by Sublime Text 2 (2011), canonized by VS Code (Ctrl+Shift+P), then spread to Superhuman/Slack/Linear/Notion (Cmd+K) and to OS-level launchers (Raycast).

**3.2 Why it serves both audiences.** VS Code's docs make the dual role explicit: "The most important key combination to know is ⇧⌘P… which brings up the Command Palette. From here, you have access to all functionality within VS Code, including keyboard shortcuts for the most common operations." A novice can find a command by name (recognition over recall — Nielsen's heuristic #6, https://www.nngroup.com/articles/ten-usability-heuristics/); an expert never leaves the keyboard; and displaying the keybinding next to each result teaches the shortcut the next time. Source: https://code.visualstudio.com/docs/getstarted/userinterface. The pattern is now so standard it's an open-source component: "⌘K is a command menu React component… You render items, it filters and sorts them automatically" (cmdk by Paco Coursey, https://github.com/pacocoursey/cmdk).

**3.3 Shortcuts as taught skills (Superhuman).** "Superhuman was famous for popularizing keyboard shortcuts for everything. Learning keyboard shortcuts is a very unusual experience. Like a piano lesson, our customers benefitted from a real human encouraging them to try new interactions, helping them turn awkward physical movement into fluid muscle memory." Source: https://review.firstround.com/superhuman-onboarding-playbook/. This is Raskin's habituation argument in product form (§1.5): interfaces should be designed so that repeated physical actions become automatic — and the on-ramp to habit is a visible hint that repeats until the habit forms.

**3.4 Training wheels that come off.** The "hint that teaches then fades" pattern is the modern implementation of two older ideas: Cooper's "Don't weld on training wheels" (§1.2) and Carroll & Carrithers' literal training-wheels interface (§6.2). Design guidance synthesized from the sources above: every contextual hint names the keyboard shortcut; hints appear at the moment of need (not up front — §2.2); and a hint that has been used successfully a couple of times should disappear so the expert interface stays dense. NN/g's tooltip guidelines (https://www.nngroup.com/articles/tooltip-guidelines/) supply the mechanics (brief, hover-anchored, non-blocking); Gmail's "?" shortcut overlay and Superhuman's per-shortcut coaching are the exemplars.

## 4. Terminals for beginners, and the safety patterns that de-risk them

**4.1 What actually helps people get comfortable (Julia Evans).** Evans surveyed readers who had recently stopped being scared of the command line; her takeaway: "There obviously isn't one single thing that works for everyone – different people take different paths." The highest-signal category was *fear reduction through risk reduction*. Verbatim tactics her readers credited: "Aliasing rm to a tool like safe-rm or rmtrash so that you can't accidentally delete something you shouldn't (or just rm -i)"; "Mostly avoid using wildcards, use tab completion instead. (my shell will tab complete rm *.txt and show me exactly what it's going to remove)"; "regular backups"; "using git as much as possible"; and "Fancy terminal prompts that tell you the current directory, machine you're on, git branch, and whether you're root." Source: https://jvns.ca/blog/2023/08/08/what-helps-people-get-comfortable-on-the-command-line-/. Her zine *The Secret Rules of the Terminal* (https://jvns.ca/blog/2025/06/24/new-zine--the-secret-rules-of-the-terminal/) documents the deeper issue: the terminal's conventions are undocumented and invisible — a Norman signifier problem (§1.3). Also: her practice of deliberately celebrating "tiny learning milestones," https://jvns.ca/blog/2022/03/13/celebrate-tiny-learning-milestones/.

**4.2 Autosuggestions and community docs.** Fish's interactive documentation describes *Autosuggestions*: fish completes commands in gray as you type, drawn from your history, accepted with one keystroke — suggestions as a learnable feature, not a menu. Source: https://fishshell.com/docs/current/interactive.html. tldr pages exist because man pages are for reference, not learning: "Simplified and community-driven man pages" with "practical examples." Source: https://tldr.sh/. Nushell attacks a different layer: replacing opaque text streams with structured data so pipelines are inspectable and errors name the wrong piece (https://www.nushell.sh/).

**4.3 The "explain before run" pattern.** Warp's Agent Mode announcement describes the contract: the agent gets "permission to run commands on your machine and use the outputs to guide you, step-by-step. It's also self-correcting when it runs into errors." Source: https://www.warp.dev/blog/agent-mode. GitHub Copilot in the CLI provides `copilot suggest` (natural language → command) and `copilot explain` (command → plain-language explanation) — turning any opaque one-liner into a teachable moment before execution. Source: https://docs.github.com/en/copilot/using-github-copilot/using-github-copilot-in-the-command-line. The pattern both sources converge on: show the command, say in words what it does, let the human approve — comprehension before power.

**4.4 Friendlier REPLs as precedent.** Jupyter/IPython proved that a REPL can be made approachable (documents that mix prose, code, and visible output; errors that name the cell) without giving up power — the same move Relay makes from plain terminal to terminal+agent workspace. (Project Jupyter, https://jupyter.org/.)

## 5. Conversational/AI onboarding: assistant that onboards by doing

**5.1 Why Clippy failed (Luke Swartz, Stanford, 2000).** The thesis abstract: "This thesis explores why many people have a negative response to the Office Assistant, using a combination of theoretical, qualitative, and quantitative studies. Among the findings were that labels — whether internal cognitive labels or explicit system-provided labels — of user interface agents can influence users' perceptions of those agents." The core etiquette failure: "The Office Assistant's letter-writing proactive help feature, thus, breaks every relevant etiquette rule: it ignores social conventions of when to disturb someone, it does not learn from its mistakes, it does not develop a long-term relationship, and (one might argue) it does not even provide a helpful service!" Source: Swartz, "Why People Hate the Paperclip," http://xenon.stanford.edu/~lswartz/paperclip/paperclip.pdf. Lessons for Relay: no unsolicited interruption, remember and adapt to the user's behavior, and earn the persona by being useful first.

**5.2 New users interrogate the bot (NN/g).** In a qualitative study of AI-chatbot first-run: "3 out of 6 participants had no prior experience with AI tools of any kind," and NN/g observed "'Can You' prompts, where new users were asking the bot about its capabilities… Therefore, the bot should possess a comprehensive self-awareness of its own capabilities and be prepared to assist users when they inquire about it." Conversely, "when the bot failed to provide accurate answers [about its own capabilities], users' understanding of the tool's capabilities was negatively impacted" — e.g., Ernie mis-describing where its file-upload feature lived. Source: NN/g, "Onboarding New AI Users," https://www.nngroup.com/articles/new-ai-users-onboarding/. This is the design case for the agent in the prompt box answering "what can you do here?" accurately, and for suggested-prompt chips (the ChatGPT/Claude/Notion AI empty-state pattern) as capability signifiers.

**5.3 One agent, clear scope (NN/g).** NN/g's chatbot guidelines include a case where two bots on one site (Home Depot's Live Chat vs. "Magic Apron") left users unable to tell which one could help — one assistant with an explicit, honestly stated scope beats a garden of ambiguous agents. Source: https://www.nngroup.com/articles/ai-chatbots-design-guidelines/.

**5.4 Trust and transparency for agents that act (NN/g).** "When it comes to AI agents, users don't always understand how these systems work, where their data goes, or why companies are pushing various features so aggressively." In NN/g's agent study, unexplained state changes (a checkout price jumping with hidden fees) broke trust — agents must show their reasoning, prices, and side effects before committing. Source: NN/g, "Designing AI Agents," https://www.nngroup.com/articles/designing-ai-agents/.

**5.5 Self-documenting input grammars (Copilot Chat).** "Slash commands as shortcuts for frequently used prompts… Type / in the chat input to see all available commands." Source: VS Code docs, https://code.visualstudio.com/docs/copilot/copilot-chat. The chat box teaches its own grammar (slash commands, agent roles, permission levels) from inside the input — exactly the discoverability pattern for a hybrid shell/agent box. Slackbot (Slack's in-product assistant that onboards new workspaces through a conversational DM) is the canonical "assistant-led onboarding done right" exemplar: it onboards by doing things with you, in context, rather than by touring you.

## 6. Anxiety, minimalist instruction, and designing for recovery

**6.1 Computer self-efficacy (Compeau & Higgins, 1995).** The MIS Quarterly abstract: "This paper discusses the role of individuals' beliefs about their abilities to competently use computers (computer self-efficacy)…" The validated finding across this literature: self-efficacy predicts computer use, persistence, and anxiety — early wins aren't cosmetic, they are the mechanism by which novices convert into users. Source: Compeau & Higgins, "Computer Self-Efficacy: Development of a Measure and Initial Test," MIS Quarterly 19(2), https://misq.umn.edu/misq/article/19/2/189/1161/Computer-Self-Efficacy-Development-of-a-Measure.

**6.2 The training-wheels interface (Carroll & Carrithers, 1984).** Abstract: "New users of high-function application systems can become frustrated and confused by the errors they make…" Their intervention, tested at IBM: a learner-facing system state that *blocks* dangerous or fatal error states so beginners can explore without catastrophic consequences — literal training wheels that come off. Source: "Training Wheels in a User Interface," Communications of the ACM 27(8), https://dl.acm.org/doi/10.1145/358198.358218.

**6.3 Minimalist instruction (Carroll, *The Nurnberg Funnel*, MIT Press 1990).** Carroll's minimalist instruction: skip the lecture, put learners on meaningful real tasks immediately, make errors and error-recovery the main learning vehicle, and support self-direction. Book page: https://mitpress.mit.edu/9780262031914/the-nurnberg-funnel/. This is the research ancestor of "learn by doing" onboarding (§2.3) and of Superhuman's "interactive" attribute (§2.5).

**6.4 Undo as infrastructure (Apple HIG).** "Let people undo multiple times… People generally expect to undo every action they've performed since taking a logical step like opening a document or saving their work." And: "Briefly and precisely describe the operation to be undone." Source: Apple Human Interface Guidelines, "Undo and Redo," https://developer.apple.com/design/human-interface-guidelines/undo-and-redo. Combined with Tog's "Protect Users' Work" and "Explorable Interfaces" (§1.4): recoverability is what turns a scary, irreversible terminal into an explorable one — recovery, not prevention, is the realistic safety net, which is also Norman's error philosophy in *The Design of Everyday Things* (design so errors are recoverable; the error is the design's fault, not the user's).

## 7. Mass design: awesome users, ethical hooks, jobs to be done

**7.1 Badass users, not badass tools (Kathy Sierra).** *Badass: Making Users Awesome* (O'Reilly, 2015) argues the entire product's job is the user's growing capability: people don't want to be good at your tool, they want to be good at the thing the tool helps them do — so design the "badass upgrade path," give early wins, and measure success as user skill, not feature usage. Book page: https://www.oreilly.com/library/view/badass-making-users/9781491919057/. For Relay: the product wins when a novice can do terminal things unaided, not when they admire the agent.

**7.2 Simple things simple, complex things possible.** The mass-vs-power synthesis is often stated via Alan Kay's aphorism "Simple things should be simple, complex things should be possible" — Apple's desktop-era playbook (progressive disclosure + strong defaults + discoverable power) operationalized it. It pairs with Nielsen's progressive disclosure (§1.1) and Cooper's intermediates (§1.2) as the three-part answer to dual-audience design.

**7.3 Hooked, minus the manipulation (Nir Eyal).** The Hook Model (trigger → action → variable reward → investment) explains why *investment* during onboarding matters: when users put something in (a project, a first command, a configured workspace), likelihood of return rises. But Eyal's own ethics screen, the Manipulation Matrix: "The matrix seeks to help you answer not, [can I manipulate my users], but [should I]?" — and his warning about "Peddlers": "designers of manipulative technology have a strong motivation to improve the lives of their users, but when pressed, they admit they would not actually use their creations." Source: https://www.nirandfar.com/the-art-of-manipulation/ (and *Hooked*, Portfolio, 2014). Rule for Relay: hooks that build user skill are legitimate; engagement loops that don't are not.

**7.4 Jobs-to-be-done for first-time use.** Clayton Christensen's canonical statement: customers don't buy products, they "hire" them to make progress in a circumstance ("Know Your Customers' Jobs to Be Done," HBR, Sept 2016, https://hbr.org/2016/09/know-your-customers-jobs-to-be-done). Bob Moesta (co-developer of the switch interview; *Demand-Side Sales 101* and The Re-Wired Group's JTBD work) extends this to *first-time use* as its own "hire" moment: onboarding should be designed around the progress the user is trying to make in the first session — interview switchers, find the forces (push of the old, pull of the new, anxiety of the new, habit of the old), and design the first run to resolve the anxiety force. For Relay, the first-session job is concrete: "get my project set up / fix this thing / understand this repo" — not "learn Relay."

## Design rules for a dual-audience terminal+agent

Concrete, testable rules derived from the sources above. Each names its source.

1. **One prompt box, one mode.** Shell commands and natural language go in the same box; routing is automatic and the decision is shown as a visible chip ("shell" / "agent") before execution — never a hidden mode. *[Raskin modelessness, §1.5; Norman signifiers, §1.3]*
2. **First run = one real task, done with the agent, in under five minutes.** The new user picks a real goal ("set up my project," "explain this error") and completes it end-to-end; no passive tour. *[Carroll minimalist instruction, §6.3; Superhuman "interactive/opinionated/interruptive," §2.5; Appcues learn-by-doing, §2.3]*
3. **No front-loaded tutorial.** Zero multi-screen coach-mark sequences at first launch; all teaching is contextual at the moment of need. A/B test: tutorial arm must not beat no-tutorial arm on day-7 activation. *[NN/g Laubheimer, §2.2]*
4. **Every empty state teaches.** Empty Board, empty terminal, and empty history each show system status plus 2–3 concrete next actions (clickable example prompts), never "nothing here yet." *[NN/g empty states, §2.6]*
5. **Progressive disclosure everywhere.** Default views show only the few most important options; advanced flags, raw logs, and power settings live one click deeper. Measure: novice task success with defaults ≥ expert-configured paths untouched. *[Nielsen, §1.1]*
6. **Hints name the key and die after use.** Every hint chip shows the keyboard shortcut; once the user has performed that action via the hint twice (or via the shortcut once), the hint never reappears. *[Cooper "don't weld on training wheels," §1.2; Carroll & Carrithers, §6.2; Superhuman piano lesson, §3.3; NN/g tooltips, §2.2]*
7. **Cmd+K/Ctrl+P palette indexes everything** — app commands, agent intents, Board actions, files — with fuzzy match, recent/frequent items first, and each row displaying its shortcut inline. *[Wikipedia/VS Code/cmdk, §3.1–3.2]*
8. **Explain before run.** Any agent-generated shell command renders with a one-line plain-language explanation and an explicit Run button; destructive commands additionally require typed confirmation. Default on for everyone in week one; downgradeable per-command-type afterward. *[Warp Agent Mode + Copilot CLI explain, §4.3; Evans risk-reduction, §4.1]*
9. **Confirm only the irreversible.** `rm -rf`, force-push, data-dropping operations get hard confirmation; everything reversible just runs and is undoable. Never stack warning dialogs on safe actions (warnings lose meaning). *[Tog explorable interfaces, §1.4; Raskin elimination of blocking warnings, §1.5]*
10. **Undo everything the agent does.** Every reversible agent action (file edit, command with side effects, Board change) is undoable from one shortcut; the undo menu names each operation precisely ("Undo: deleted build/"). *[Apple HIG undo, §6.4]*
11. **Training-wheels sandbox for first sessions.** New users can run everything in a throwaway demo workspace; destructive operations in their real workspace stay gated until they opt in. *[Carroll & Carrithers training wheels, §6.2]*
12. **Preview what a command will hit.** Before running a wildcarded or recursive command, show the expansion (the exact files affected), like fish/tldr-style previews. *[Evans: tab-complete `rm *.txt` to see what's removed, §4.1]*
13. **Suggestions teach the box.** The idle prompt box rotates 3 contextual suggestions (from the actual project) and the agent always answers "what can you do here?" accurately; suggested prompts must never promise a capability that fails. *[NN/g AI onboarding "Can You" prompts + Ernie failure, §5.2]*
14. **Self-documenting grammar.** Typing `/` lists agent commands with descriptions; typing `@` lists attachable contexts (files, panes, Board cards). No documentation visit required to discover either. *[VS Code Copilot Chat, §5.5]*
15. **Instrument one activation behavior.** Define Relay's "2,000 messages": e.g., first Board card moved to Done via an agent-assisted session inside 48 hours; every onboarding change is judged on moving that metric, not on clicks. *[Slack/Facebook activation metrics, §2.4; Superhuman user states, §2.5]*
16. **Personalize with two questions at signup.** "How comfortable are you with terminals?" and "What are you working on?" — answers set hint density, agent verbosity, and default layout. Nothing else asked up front. *[Appcues personalization, §2.3; NN/g low-AI-literacy users need extra help, §5.2]*
17. **Density is a dial with persona defaults.** Compact mode (tight spacing, minimal labels) vs. Guided mode (labels, whitespace, explanations); novices default to Guided, experts to Compact, both switchable anytime. *[Cooper perpetual intermediates, §1.2; progressive disclosure, §1.1]*
18. **The agent never interrupts.** No unsolicited popups, no mascot; proactive suggestions appear only in the prompt area or Board, are dismissible with Esc, and the agent adapts when dismissed twice. *[Swartz/Clippy etiquette rules, §5.1]*
