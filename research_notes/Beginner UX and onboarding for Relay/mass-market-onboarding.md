# Mass-market onboarding research for Relay's first-run experience

How ten mass-market products handle first launch, the blank canvas, and teaching power to non-technical users — with concrete screens, copy, steps, and what changed over versions — followed by transferable patterns and anti-patterns for Relay, a terminal that must be obvious to a professor, lawyer, journalist, or student and fast for an expert.

---

## 1. Microsoft Word / Office: blank vs. templates, search in the ribbon, and the ghost of Clippy

**The Start screen (Word 2013).** Word 2013 replaced the launch-to-blank behavior with a full Start screen: a searchable template gallery with pinnable favorites, where Blank Document is simply the first tile. The official Microsoft 365 blog post about the design contains the key data point: *"We know that over half of all Word sessions start from a blank document."* Microsoft's response was not to fight the blank preference but to segment it — adding more blank templates such as "Single spaced (blank)" and "Report design (blank)" that open pre-formatted with the most-used styles, one click from the Start screen. Templates double as a feature tour: opening one shows you styles, headers, and layout you didn't know existed. (https://www.microsoft.com/en-us/microsoft-365/blog/2012/10/31/starting-from-blank-design-templates-in-the-word-2013/)

**The Ribbon as discoverability.** Jensen Harris, Office UX lead, recounts that the redesign began in summer 2003 to fix *"complicated software with many commands, befuddled users, and too many ways to do the same thing."* The Ribbon's innovations were results-up-front (galleries of live previews instead of dialog boxes of options) and a group-prioritization system: every "chunk" has four designs (large, medium, small, collapsed) and priority ordering decides which groups survive as the window shrinks. The transferable idea: a persistent UI must show a prioritized few commands well rather than everything — which is why Relay's chrome should expose a handful of actions, not the full surface. (https://jensenharris.com/home/ribbon; the MIX08 talk "The Story of the Ribbon" is linked there)

**"Tell me what you want to do."** Office 2016 put a natural-language box directly in the Ribbon chrome: *"a text field where you can enter words and phrases about what you want to do next and quickly get to features you want to use or actions you want to perform."* It also surfaced help, Smart Lookup definitions, and people from the company directory. Microsoft openly A/B-tested the affordance: *"you may see Search instead of Tell me what you want to do in the ribbon. The functionality is identical, we're just trying out some new ideas to make it more discoverable."* It was renamed Search, and today the same support docset routes you to Copilot ("Get help with Copilot") — the arc is menu → toolbar → ribbon → natural-language search box → conversational agent, all solving the same problem: users don't know the command's name. That is precisely Relay's one-prompt-box premise, thirty years early. (https://support.microsoft.com/en-us/office/do-things-quickly-with-tell-me)

**Clippy as the cautionary tale.** The Office Assistant shipped in Office 97 (internally code-named TFC — "That Fucking Clown"). Microsoft disabled it by default in Office XP (2001) and ran a marketing campaign *mocking* it — flash cartoons, and an Office XP launch stunt where the Clippit mascot begged for his job before being dragged off stage — before removing it entirely in Office 2007 (Jan 30, 2007). In 2011 Office Labs shipped *Ribbon Hero 2: Clippy's Second Chance*, a puzzle game to teach the new UI — an admission that teaching had failed the first time. Failures to avoid: help that interrupts uninvited, guessing intent wrong *in front of* the user, and personality that becomes ridicule. (https://en.wikipedia.org/wiki/Office_Assistant)

## 2. GitHub: a guided first repo, then a copy-paste empty state

**New-account onboarding.** GitHub's July 2021 changelog describes the current flow: after signup the homepage guides new users through profile setup and first actions — *"From the homepage's vantage point in outer space, we'll guide you to a soft landing and get you started in no time"* — a deliberately themed, celebratory tone instead of an enterprise checklist, with a "read the guide" path into the Hello World guide and a personalized homepage afterward. (https://github.blog/changelog/2021-07-19-a-redesigned-new-user-onboarding-experience/)

**Hello World guide.** The canonical "guided first artifact": *"Follow this Hello World exercise to learn GitHub's pull request workflow… You'll create your own Hello World repository"* — you make a repo, edit the README in the browser editor, start a branch, and open and merge a pull request, learning repos/branches/commits/PRs in minutes without touching a CLI. (https://docs.github.com/en/get-started/start-your-journey/hello-world; hub: https://docs.github.com/en/get-started/onboarding)

**The empty-repository page.** GitHub's most-copied onboarding artifact is titled **"Quick setup — if you've done this kind of thing before."** That subtitle is an expert skip path written into the empty state itself: experts self-identify and are gone in seconds, while novices get HTTPS/SSH/CLI/Desktop buttons and literal copy blocks — "…or create a new repository on the command line" and "…or push an existing repository from the command line" — each with a one-click copy icon. Every empty screen in Relay can carry this dual address. (https://docs.github.com/en/repositories/creating-and-managing-repositories/quickstart-for-repositories)

**GitHub Desktop first-run.** Install → authenticate (Sign in to GitHub, or GitHub Enterprise) → "Creating your first repository," with a workflow sidebar tour (clone, branch, view PRs). (https://docs.github.com/en/desktop/overview/getting-started-with-github-desktop) **Copilot onboarding** similarly starts from a quickstart with concrete example prompts and inline suggestion accepting. (https://docs.github.com/en/copilot/get-started/quickstart-for-using-github-copilot-on-github-com)

## 3. Notion: templates first, and a tutorial you can delete

**One intent question, five personalized templates.** At signup Notion asks who you are, then fills the sidebar with a personalized set of five templates matched to your role — Appcues' teardown: *"Since we said we were in marketing, we've been given a shortlist of marketing-related templates"* — each opening in a preview modal with demo data already inside. The template gallery *is* the feature tour: demo content shows databases, relations, and embeds in use. (https://goodux.appcues.com/blog/notions-lightweight-onboarding)

**The Getting Started page teaches by being edited.** Notion's first-run "Getting Started" page is a real Notion page of checkboxes and to-dos; completing it *is* the practice. Appcues calls this "learn-by-doing onboarding," noting users are free to explore and can simply delete the tutorial when done — onboarding content lives inside the product surface and is disposable. Supademo's screen-by-screen teardown adds the current shape: a single question (Work/Personal/School) routes you to a tailored workspace with an onboarding checklist and template suggestions, an optional AI-generated starter page, and measured activation — a first functional page — in roughly 3–6 minutes. (https://goodux.appcues.com/blog/notions-lightweight-onboarding; https://supademo.com/user-flow-examples/notion)

**Slash commands as discovery.** The empty page whispers its own affordance: type `/` and a menu of every insertable block appears. Notion's own guide: *"To add content, hit the slash key, and select or type the content type (e.g. /image)"*, plus `/quote`, `/callout`, `/red` (color), `/turnbullet` (change block type), `/comment`, `/duplicate` — and `?` alone shows keyboard shortcuts. The slash menu is a browsable, searchable index of the whole product: a power-user accelerator that doubles as novice feature discovery. This is the exact contract Relay's prompt box should offer. (https://www.notion.com/help/guides/using-slash-commands)

## 4. Figma: onboard inside a real file

Figma's first-run drops **interactive example files** — real, seeded design files — directly into your workspace rather than linking out to tutorials, wrapped in a short feature tour and template gallery. Supademo's teardown concludes: *"Figma's onboarding makes a deliberate choice: it doesn't hide the tool's complexity, it contextualizes it,"* and names the primary risk as blank-canvas intimidation *before* users find the example files — so the seeded files arrive first. Notably, Figma defines activation as "designing a first real layout inside a Figma file" and accepts ~30 minutes to get there: pro tools don't fake a five-minute "aha"; they scaffold a real one. (https://supademo.com/user-flow-examples/figma) Figma's help center "Get started" category backs the in-product learning with short basics courses. (https://help.figma.com/hc/en-us/categories/360002051613-Get-started)

## 5. Slack: a workspace that arrives pre-filled

Slack's modern onboarding (Userpilot's teardown) refuses the empty shell: *"Instead of dropping you into an empty workspace and layering tooltips on top, Slack hands you a workspace that's already set up."* Signup runs about nine steps to a workspace; Slack auto-creates channels (named after your company, plus a "new-channel" and a "social" channel), and each channel opens with a short welcome message explaining its purpose followed by **two or three native task cards** — invite teammates, create a welcome message — that *"read like part of the channel rather than a regular user onboarding checklist, so they guide you without ever blocking you."* A welcome survey asks about org size and plans, and the free-trial pitch is revealed only at the end, after the workspace is alive. (https://userpilot.com/blog/slack-onboarding/) Slack's official help center maintains a dedicated "Getting started for new Slack users" path. (https://slack.com/help/articles/218080037) The classic Slackbot DM — Slack's built-in assistant greeting new users — is the archetype of the *chat-as-teacher* pattern: education delivered in the product's own native format (a conversation), skippable by closing the thread.

## 6. Superhuman: 30-minute human onboarding, then self-serve

Superhuman famously made signup *harder*: book a 30-minute live 1:1 call (originally a Calendly link) before you could use a $30/month email client. A teardown of the call shows its structure to the minute: agenda (0:00–0:02), learn your workflow (0:02–0:07), configure the app live (0:07–0:25 — split-pane, snippets, instant-intro shortcuts), then one "magic moment" (0:25–0:30 — usually ⌘K "Jump" to any conversation in under 300 ms). The pre-call survey doubled as effort justification: effort invested raised perceived ROI. (https://www.flowjam.com/blog/superhuman-onboarding-teardown-30-minute-wow-session) Rahul Vohra told Lenny Rachitsky that at peak Superhuman employed **20 full-time people** doing manual onboarding, which "created superfans and allowed engineers to focus on product rather than onboarding flows." (https://www.lennysnewsletter.com/p/superhumans-secret-to-success-rahul-vohra) The same operation ran on the famous PMF engine: a Typeform survey of active users asking how they'd feel if they could no longer use the product, with Sean Ellis's 40% "very disappointed" benchmark as the gate. (https://review.firstround.com/how-superhuman-built-an-engine-to-find-product-market-fit/) As the market broadened, Superhuman moved from human-led to self-serve onboarding (First Round documented the transition), keeping the human touch for qualified accounts — "qualify first, let everyone else self-serve." (https://review.firstround.com/inside-superhumans-onboarding-strategy-from-human-led-to-self-serve/) And the keyboard-first teaching survives in-product: *"In Superhuman, one shortcut rules them all: Cmd+K. Cmd+K brings up Superhuman Command, where you can instantly do any action — and also learn the shortcut for next time."* Every palette invocation is a micro-lesson. (https://blog.superhuman.com/how-to-build-a-remarkable-command-palette/)

## 7. Arc and Linear: the story vs. the checklist

**Arc** onboards with an illustrated, story-like intro sequence and strong opinionated defaults — import from Chrome, make Arc your default, Spaces instead of tab chaos — before showing the browser. Screenshot catalogs document the flow (https://www.saasui.design/pattern/onboarding/arc-browser). The criticism is instructive: on Hacker News, would-be users complained that the charming onboarding ended at *"a wall of mandatory Arc account creation,"* and dismissed the "fancy onboarding" as too long relative to first value (https://news.ycombinator.com/item?id=40216193). Delight that delays value becomes friction.

**Linear** does the opposite — onboarding that teaches its power features first. Supademo's teardown: *"Linear teaches Cmd+K before the workspace is populated — not as a shortcut the user might like, but as the model for how the product works."* Right after workspace creation it asks a cosmetic question (light/dark), then hands you a "get familiar with Linear" checklist that teaches through action — create an issue, use the command menu, set a priority — where *"most products introduce keyboard shortcuts in a tips section or a late-stage onboarding email."* Crucially, Linear's activation event is **completing and resolving** the first issue, not merely creating one. (https://supademo.com/user-flow-examples/linear)

## 8. Apple: don't front-load, teach in context

Apple's Human Interface Guidelines "Onboarding" page is the tersest articulation of the principles in this document: *"if onboarding is necessary, design a flow that's fast, fun, and optional"*; *"provide an interactive onboarding experience where people can safely test an action, discover a feature, or try out a game mechanic"*; *"consider providing a collection of context-specific tips instead of a single onboarding flow"*; and on skipping: *"If you let people skip the tutorial… don't present it again on subsequent launches, but make sure it's easy for people to find."* (https://developer.apple.com/design/human-interface-guidelines/onboarding) The companion "Launching" page adds that a launch screen's *"sole function is to enhance the perception of your experience as quick to launch and immediately ready to use"* — never branding, never a billboard. (https://developer.apple.com/design/human-interface-guidelines/launching) The same restraint governs iPhone/macOS Setup Assistant: progressive steps, each with a defer-or-later escape, no manual.

**Pages/Numbers.** Pages embodies templates-first: *"Every time you create a new document, you choose a template from the template chooser,"* with placeholders that show the document's styles in context — and a deliberate commitment rule: *"After you begin creating your document, you can't switch to a different template."* Templates are even segmented by document architecture (word-processing like Essay and School Newsletter vs. page-layout like Tab Flyer and Museum Brochure). (https://support.apple.com/guide/pages/use-templates-tan5c52a733c/mac)

## 9. Duolingo, Canva, ChatGPT, Claude: value before registration, prompts instead of blank fields

**Duolingo** front-loads the product (pick a language, set a daily goal, start learning) and monetizes *return*: the daily goal and streak mechanics are its core retention loop. growth.design's teardown includes the essential caution: *"Streaks make people come back more, but losing a streak is also a big reason why people quit"* — progress mechanics must be forgiving, or they become the reason users churn. (https://growth.design/case-studies/duolingo-user-retention)

**Canva** is template-first taken to its logical end. Supademo's teardown: *"Canva's strongest onboarding decision is the one most users don't notice: there is no blank canvas."* A single use-case question (Personal/Work/Education/Nonprofit) *"takes two seconds and doesn't delay dashboard access"*; the design canvas opens pre-filled from a template; and signup is deferred — *"the CTA meets them there instead of redirecting attention toward registration."* The named risk is the opposite extreme: AI feature density (Magic Studio tools) creates decision overload. (https://supademo.com/user-flow-examples/canva)

**ChatGPT and Claude** solved the empty-chat field the same way: suggested prompt starters — the empty state advertises capability instead of describing it, and a UX pattern catalog now treats "Prompt Starters" as a standard input pattern across ChatGPT, Claude, and Perplexity. (https://www.aiuxplayground.com/pattern/empty-state/) Claude's official "Get started" article shows how novice-targeted the example copy is: a prompt is explained via *"How do I hang a picture frame in my room?"* — an everyday task, not a developer demo — with guidance to *"Iterate: refine your prompts or ask follow-up questions"* and *"Explore: try different types of tasks."* (https://support.claude.com/en/articles/8114491-get-started-with-claude) For Relay: suggested first prompts should name household-grade tasks ("Organize these files by date"), not `ls -la`.

## 10. Games: never a manual — teach through doing

**Super Mario Bros. World 1-1** is the canonical textless tutorial. As one level-design analysis puts it: *"They did not give players a 100 page manual, and they did not fill the screen with text like 'Press A to Jump!'"* The first Goomba walks straight at you while blocks above constrain your jump; dying costs nothing *"because it is the very beginning of the game"*; contact teaches enemy vs. friend by reward and punishment. Every element (question blocks, pipes, gaps, power-ups) is introduced alone in a safe configuration, then combined. (https://medium.com/@yarenturk508/the-invisible-teacher-how-super-mario-bros-world-1-1-teaches-us-game-design-90784773af5f; video essay: https://www.youtube.com/watch?v=ZH2wGpEZVgE)

**Portal** builds the tutorial into the fiction: each test chamber isolates exactly one mechanic, the chambers make failure safe and even funny, and the "invisible tutorial" structure means players learn momentum, portals, and timing *as gameplay*. (https://www.youtube.com/watch?v=_7FQz90ef0A) **Half-Life 2** — Valve's own GDC 2006 session on its design process documents the same doctrine: teach through environment and scripted play, validated by relentless playtesting, with no manuals and no cutscene lectures. (https://gdcvault.com/play/1013237/Valve-s-Design-Process-for) The transferable doctrine: users learn your product the way players learn games — by doing one thing, safely, in context, then the next. Notion's Getting Started page, Figma's seeded files, and Linear's action checklist are this doctrine wearing enterprise clothes.

## Synthesis: principles for a product that must be obvious to novices and fast for experts

The through-line across all ten: nobody teaches features anymore. The best products teach *one concrete piece of real work*, in the product's own surface, with an escape hatch for people who already know. For Relay specifically, the agent and the terminal share one prompt box, so Relay can fuse the two strongest patterns in this research — Word's "Tell me" natural-language escape hatch and Slack's chat-as-teacher — into a single affordance.

### Transferable patterns (with exemplars)

1. **Templates-first; blank is one tile, not the whole screen.** Word 2013 Start screen (https://www.microsoft.com/en-us/microsoft-365/blog/2012/10/31/starting-from-blank-design-templates-in-the-word-2013/), Canva's "no blank canvas" (https://supademo.com/user-flow-examples/canva), Pages' mandatory template chooser (https://support.apple.com/guide/pages/use-templates-tan5c52a733c/mac). Relay: the first-run screen offers workspace templates (Research project, Code project, Course notes), not a bare shell.
2. **Segment the blank instead of fighting it.** Over half of Word sessions start blank, so Microsoft shipped "Single spaced (blank)" — blank, but with the good defaults baked in. Relay: "Blank workspace" variants (with/without README, with a starter Board).
3. **Pre-populate; never open to an empty shell.** Slack auto-creates channels with welcome messages and task cards (https://userpilot.com/blog/slack-onboarding/); Notion ships a personalized starter workspace (https://supademo.com/user-flow-examples/notion).
4. **The product is the tutorial.** Notion's Getting Started page is a deletable real doc (https://goodux.appcues.com/blog/notions-lightweight-onboarding); Figma seeds interactive example files (https://supademo.com/user-flow-examples/figma). Relay: the first Board is the tutorial — cards that teach by being completed.
5. **Action checklists beat passive tours.** Linear's "get familiar" checklist makes you *do* the product (https://supademo.com/user-flow-examples/linear); Slack's task cards "guide without ever blocking" (https://userpilot.com/blog/slack-onboarding/).
6. **Empty states are instruction with a copy button.** GitHub's "Quick setup — if you've done this kind of thing before" (https://docs.github.com/en/repositories/creating-and-managing-repositories/quickstart-for-repositories). Relay: an empty pane offers "Paste this to try" examples.
7. **One guided first artifact, end to end.** GitHub Hello World (repo→branch→PR) (https://docs.github.com/en/get-started/start-your-journey/hello-world); Linear activation is a *resolved* issue (https://supademo.com/user-flow-examples/linear). Relay activation: one command run + one agent task done + one card moved to Done.
8. **A searchable command surface doubles as discovery.** Notion `/` (https://www.notion.com/help/guides/using-slash-commands), Superhuman ⌘K (https://blog.superhuman.com/how-to-build-a-remarkable-command-palette/), Linear ⌘K taught before anything else (https://supademo.com/user-flow-examples/linear), Word Tell Me (https://support.microsoft.com/en-us/office/do-things-quickly-with-tell-me). Relay's prompt box should autocomplete both commands and plain-English intents.
9. **Teach the shortcut at the moment of use.** Superhuman Command shows the shortcut "for next time" on every action — every palette use is a micro-lesson that graduates novices toward expert speed. (https://blog.superhuman.com/how-to-build-a-remarkable-command-palette/)
10. **One intent question, then personalize.** Notion's Work/Personal/School routing (https://supademo.com/user-flow-examples/notion); Canva's two-second use-case question that doesn't delay the dashboard (https://supademo.com/user-flow-examples/canva). One question max; never a survey wall.
11. **Build expert skip paths into the same screen.** GitHub's empty-repo subtitle self-selects experts (https://docs.github.com/en/repositories/creating-and-managing-repositories/quickstart-for-repositories); Apple's rule: skippable, never re-shown, but findable (https://developer.apple.com/design/human-interface-guidelines/onboarding).
12. **Teach one thing, in context, when it's needed.** Apple's "collection of context-specific tips instead of a single onboarding flow" (https://developer.apple.com/design/human-interface-guidelines/onboarding); Portal's one-mechanic-per-chamber (https://www.youtube.com/watch?v=_7FQz90ef0A).
13. **Make practice safe to fail.** Apple: "safely test an action" (https://developer.apple.com/design/human-interface-guidelines/onboarding); Mario's first Goomba kills you at zero cost (https://medium.com/@yarenturk508/the-invisible-teacher-how-super-mario-bros-world-1-1-teaches-us-game-design-90784773af5f). Relay: the first-run sandbox project is disposable by design.
14. **Defer credentials until after first value.** Canva: "the CTA meets them there instead of redirecting attention toward registration" (https://supademo.com/user-flow-examples/canva); Slack reveals the trial pitch only at the end (https://userpilot.com/blog/slack-onboarding/). Arc's forced account wall is the counterexample (https://news.ycombinator.com/item?id=40216193). Relay: agent sign-in asked at the first agent request, not at launch.
15. **Chat as teacher — invited, native, closable.** Slack's assistant DM and Slack's own conversational format (https://userpilot.com/blog/slack-onboarding/); Copilot as the descendant of Tell Me (https://support.microsoft.com/en-us/office/do-things-quickly-with-tell-me). The assistant answers in the product's native medium and never blocks work.
16. **Humans for high-touch moments, then automate.** Superhuman scaled 20 full-time onboarding staff into a self-serve flow, keeping humans for qualified accounts (https://www.lennysnewsletter.com/p/superhumans-secret-to-success-rahul-vohra; https://review.firstround.com/inside-superhumans-onboarding-strategy-from-human-led-to-self-serve/).
17. **Measure activation as real value created, and publish the clock.** Notion: first functional page in 3–6 min (https://supademo.com/user-flow-examples/notion); Figma accepts ~30 min to a first real layout (https://supademo.com/user-flow-examples/figma). Pick Relay's activation event before designing the tour.

### Anti-patterns (with the product that proves them)

1. **Unsolicited interruption.** Clippy guessed intent and interrupted mid-task; Microsoft mocked it in its own ads, then deleted it. (https://en.wikipedia.org/wiki/Office_Assistant)
2. **Personality over utility.** A mascot users laugh *at* ("That Fucking Clown" was the internal codename) teaches nothing. Delight must ride on function. (https://en.wikipedia.org/wiki/Office_Assistant)
3. **Front-loaded memorization tours.** Apple's HIG warns against making people "memorize a lot of information" before use; Arc's story-length onboarding drew exactly this complaint. (https://developer.apple.com/design/human-interface-guidelines/onboarding; https://news.ycombinator.com/item?id=40216193)
4. **Credentials or setup walls before value.** Arc's mandatory account creation; Superhuman's call worked only because the waitlist made it exclusive — don't copy the gate, copy the magic moment. (https://news.ycombinator.com/item?id=40216193)
5. **The blank canvas with zero scaffolding.** Word's own data (50%+ blank sessions) shows users flee to blank when templates are buried; Figma names blank-canvas intimidation as its top onboarding risk. (https://www.microsoft.com/en-us/microsoft-365/blog/2012/10/31/starting-from-blank-design-templates-in-the-word-2013/; https://supademo.com/user-flow-examples/figma)
6. **Feature-density overload at first open.** Canva's AI-tool sprawl is its teardown's named risk: too many magic buttons paralyze. (https://supademo.com/user-flow-examples/canva)
7. **An empty shell with tooltips on top.** The exact pattern Slack's onboarding was built to replace. (https://userpilot.com/blog/slack-onboarding/)
8. **Progress mechanics that punish.** Duolingo's streak: drives return visits, and losing one is "a big reason why people quit." Any Relay streak/count must be repairable. (https://growth.design/case-studies/duolingo-user-retention)

### What this means for Relay's first run (concrete)

- **Launch screen:** template row (Research, Code, Course, Blank variants) + a one-question intent ask; expert "Skip — I've done this before" link, GitHub-style.
- **First workspace:** pre-seeded — one terminal pane with a suggested first command, one agent pane, one Board holding the tutorial checklist as cards (run a command, ask the agent, split a pane, move this card to Done).
- **Prompt box:** Tell Me-style placeholder copy ("Type a command, or describe what you want"), slash-prefix for command discovery, ⌘K palette that displays the shortcut for next time on every action.
- **Agent introduction:** a Slackbot-style first message in the agent pane that demonstrates rather than describes ("I just listed your files — want me to organize them?"), invited and closable, never modal.
- **Sign-in:** deferred to the first agent request; local shell features work immediately.
- **Activation metric:** first command executed + first agent reply + first card completed; time-to-value instrumented per Notion/Figma practice.
