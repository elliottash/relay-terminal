# Editable terminal and creative workspaces for Relay (September 2026)

## How do AI coding systems combine an editor, terminal, and live manual plus agent editing?

### Takeaway
The strongest documented pattern is a shared workspace with separate surfaces for conversation, editable artifacts, commands, and review. Products differ sharply in whether an agent writes directly to the working tree, uses a pending-edit overlay, or works in an isolated copy that must be applied later.

### Cited Findings
- **Cursor:** Agent can search, edit multiple files, run terminal commands, and fix errors; Manual mode confines edits to files the user explicitly selects. Its agent terminal preserves history and has an interrupt control. Its review UI supports per-file and selective line acceptance, while checkpoints track only agent changes, not manual edits. — [Modes](https://docs.cursor.com/agent); [Terminal](https://docs.cursor.com/en/agent/terminal); [Diffs & Review](https://docs.cursor.com/en/agent/review); [Checkpoints](https://docs.cursor.com/en/agent/chat/checkpoints)
- **VS Code/Copilot:** Current Agent Host sessions save edits directly in a folder or isolated Git worktree; the Changes view offers single-file or multi-file diffs, range-based feedback, reviewed marks, and commit/merge/discard actions. The changed-file list covers file-edit tools but excludes files changed only through terminal commands. Older extension-host sessions instead mark saved edits as pending for Keep/Undo. VS Code recommends syncing the base before starting an isolated session to reduce merge conflicts. — [Review and revert agent changes](https://code.visualstudio.com/docs/agents/run/review-code-edits)
- **VS Code/Copilot:** The Agents window includes Files and Changes beside chat, and can open a localhost URL from chat or terminal in an integrated browser for validation. Standard Markdown preview can sit beside its source and update in real time as the text changes. — [Agents window](https://code.visualstudio.com/docs/agents/run/agents-window); [Markdown in VS Code](https://code.visualstudio.com/Docs/languages/markdown)
- **Zed:** Its Agent Panel can follow the files an agent touches, show changed-file counts, and open a multi-buffer diff with keep/reject at hunk or whole-set level. Multiple threads can run independently; Zed recommends a linked Git worktree if threads might edit the same files. Zed distinguishes its native agent, ACP external agents, and terminal-backed CLI threads; the latter two retain their own configuration/runtime boundaries. — [Agent Panel](https://zed.dev/docs/ai/agent-panel); [Parallel Agents](https://zed.dev/docs/ai/parallel-agents); [External Agents](https://zed.dev/docs/ai/external-agents)
- **Aider:** The CLI can run next to any editor; `--watch-files` reads saved `AI!`/`AI?` comments as edit/question requests, turning source-file changes into an agent input channel. Aider normally commits each agent edit and first commits preexisting dirty changes to separate manual work from its own. `/undo` uses that Git history. — [Aider in your IDE](https://aider.chat/docs/usage/watch.html); [Git integration](https://aider.chat/docs/git.html)
- **Claude Code:** Anthropic's VS Code extension places Claude in a sidebar and shows real-time inline diffs; its marketplace listing says it uses current-file/selection context and runs terminal commands with permission. The terminal interface remains a separate supported surface. — [Anthropic announcement](https://www.anthropic.com/news/enabling-claude-code-to-work-more-autonomously); [Claude Code extension](https://marketplace.visualstudio.com/items?itemName=anthropic.claude-code)
- **Codex:** OpenAI describes its IDE extension as running in VS Code, Cursor, and VS Code forks so users can preview local changes and edit code in the editor. Its Codex app supports Git worktrees for isolated runs and reviewable diffs; Codex is also available in a CLI. — [OpenAI Codex upgrades](https://openai.com/index/introducing-upgrades-to-codex/); [Long-horizon Codex workflow](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex); [OpenAI code-generation guide](https://developers.openai.com/api/docs/guides/code-generation)
- **Replit:** Its Project Editor has movable editor, Agent, Preview, Console, and Shell tabs in split panes. Background Agent tasks run in isolated project copies; the Ready state asks the user to inspect work log, tests, and preview before applying changes to main. Replit says Agent handles conflicts automatically when applying multiple tasks, without specifying a conflict-resolution algorithm on that page. Checkpoints capture project contents, AI memory, and database state. — [Editor and tools](https://docs.replit.com/features/editor/editor-and-tools); [Task board](https://docs.replit.com/features/agent/task-board); [Version control](https://docs.replit.com/learn/projects-and-artifacts/version-control)

### Inferences
- Relay can give its terminal a durable place in a broader workspace while keeping agent turns, open files, rendered outputs, and changes visible as distinct panes. The supported precedent is Zed's agent/terminal thread distinction plus VS Code's session Files/Changes and Replit's movable tool tabs. — [Zed Parallel Agents](https://zed.dev/docs/ai/parallel-agents); [VS Code Agents window](https://code.visualstudio.com/docs/agents/run/agents-window); [Replit editor](https://docs.replit.com/features/editor/editor-and-tools)
- A shared working tree needs a provenance model beyond “agent changed this file”: terminal commands, external editors, and manual edits can all touch the same path, while at least VS Code's agent change list omits terminal-only writes and Cursor's checkpoints omit manual edits. A filesystem-level change ledger with actor/command association where known would make review more honest. — [VS Code review](https://code.visualstudio.com/docs/agents/run/review-code-edits); [Cursor checkpoints](https://docs.cursor.com/en/agent/chat/checkpoints)

### Gaps
- The cited product docs do not establish a common guarantee for simultaneous human and agent edits to the same *unsaved* buffer. File watch and Git worktree guidance address saved files or separate checkouts, not a universal text-merge protocol. — [Aider watch mode](https://aider.chat/docs/usage/watch.html); [Zed worktree isolation](https://zed.dev/docs/ai/parallel-agents)
- Replit states that its Agent handles task-apply conflicts automatically, but the cited documentation does not specify what is shown to the user for an unresolved semantic conflict. — [Replit task board](https://docs.replit.com/features/agent/task-board)

## What do scripts, visual art, CAD, and diagrams teach about editable previews and pane layout?

### Takeaway
Creative systems tie an editable source or object model to a purpose-built view, often with an explicit run, render, regenerate, or commit boundary. The preview can be interactive and spatial; treating every artifact as plain text would lose the feedback that makes these workspaces useful.

### Cited Findings
- **JupyterLab:** A workspace saves open documents, activities, tabs, and layout. Users can split/rescale the main area and place editors, notebooks, consoles, terminals, Markdown previews, images, PDFs, and linked or cloned outputs in different areas. Terminals and kernels can keep running after their tabs close and can be reopened from the Running panel. — [Interface](https://jupyterlab.readthedocs.io/en/stable/user/interface.html); [Interface customization](https://jupyterlab.readthedocs.io/en/stable/user/interface_customization.html); [Managing kernels and terminals](https://jupyterlab.readthedocs.io/en/stable/user/running.html)
- **Posit/RStudio:** The default arrangement separates source, console/terminal, environment, and output (including Plots and Viewer). A `.qmd` file can switch between source and visual editing, render on save, and show inline chunk output or a side-by-side HTML/PDF preview; the preview refreshes on re-render. Long-running scripts can use Background Jobs while editing continues. — [Pane layout](https://docs.posit.co/ide/user/ide/guide/ui/ui-panes.html); [Quarto integration](https://docs.posit.co/ide/user/ide/guide/documents/quarto-project.html)
- **Blender:** Any area can host a 3D Viewport, image editor, node editor, text editor, Python console, or other editor type. Its Scripting workspace combines script editing and Python commands with the scene; scripts run explicitly from the Text Editor, while the console gives immediate feedback. Viewport Render provides a quicker preview distinct from a final render. — [Editor areas](https://docs.blender.org/manual/en/latest/editors/index.html); [Python API quickstart](https://docs.blender.org/api/5.2/info_quickstart.html); [Viewport Render](https://docs.blender.org/manual/en/3.0/editors/3dview/viewport_render.html)
- **Krita:** Workspaces save dock placement and grouping; multiple views can show the same image, and window layouts support multiple monitors. This is a canvas-centered layout pattern, rather than a source-editor-centered one. — [Workspaces](https://docs.krita.org/en/reference_manual/resource_management/resource_workspace.html); [Basic concepts](https://docs.krita.org/en/user_manual/getting_started/basic_concepts.html)
- **Onshape CAD:** A Feature Studio edits FeatureScript and autosaves keystrokes, but a separate **Commit** applies that code throughout the document. A Part Studio has a feature list plus model graphics; feature dialogs provide a before/after opacity preview before acceptance. Linked custom features are pinned to versions and notify users when a newer version is available. — [Feature Studios](https://cad.onshape.com/help/Content/FeatureStudio/feature_studios.htm); [Part Studios](https://cad.onshape.com/help/Content/PartStudio/part_studios.htm); [Feature Basics](https://cad.onshape.com/help/Content/PartStudio/feature_basics.htm); [Custom features](https://cad.onshape.com/help/Content/PartStudio/add_custom_features.htm)
- **Figma Make/Sites:** Make combines agent prompts, an interactive preview, a code editor, and point-and-edit controls on preview elements; prompts update the preview after the agent changes code. In Sites code layers, selecting a preview element can expose editable properties or jump to its source; revisions get chat checkpoints. Make's file explorer allows editing existing files but says users must prompt the agent to create files. — [Edit a Make file](https://help.figma.com/hc/en-us/articles/42009840449175-Edit-a-Figma-Make-file); [Edit a code layer](https://help.figma.com/hc/en-us/articles/32596943880599-Edit-a-code-layer); [Edit Make code](https://help.figma.com/hc/en-us/articles/33649966245783-Edit-the-code-of-a-functional-prototype-or-web-app)
- **Figma Design:** Dev Mode compares visual versions side by side or as an opacity overlay, lists edited/added/deleted layers, and can show property or generated-code differences. Branch review likewise supports side-by-side/overlay comparison and conflict resolution, though branch merges apply all changes rather than selected ones. — [Compare changes in Dev Mode](https://help.figma.com/hc/en-us/articles/15023193382935-Compare-changes-in-Dev-Mode); [Merge branch](https://help.figma.com/hc/en-us/articles/5691189138839-Merge-branch-into-main-file)
- **Mermaid and draw.io:** Mermaid's Live Editor pairs diagram code with an instant rendered preview. A July 2026 draw.io change converts Mermaid to native editable shapes while retaining source for regeneration; shape styling survives regeneration, but geometry moves do not. An older draw.io manual still says Mermaid converted to shapes cannot have source re-edited, so the dated 2026 announcement and older manual conflict on current behavior. — [Mermaid Live Editor guide](https://mermaid.js.org/intro/getting-started.html); [draw.io July 2026 update](https://www.drawio.com/blog/mermaid-updates/); [older draw.io manual](https://www.drawio.com/docs/manual/insert/insert-mermaid/)

### Inferences
- Relay could treat an artifact as a **source, run/render action, output, and view state**. Jupyter/Posit keep runtime and preview alongside source; Onshape's explicit Commit and Blender's explicit Run Script show why a preview should disclose which source revision produced it. — [JupyterLab interface](https://jupyterlab.readthedocs.io/en/stable/user/interface.html); [Posit Quarto](https://docs.posit.co/ide/user/ide/guide/documents/quarto-project.html); [Onshape Feature Studios](https://cad.onshape.com/help/Content/FeatureStudio/feature_studios.htm); [Blender quickstart](https://docs.blender.org/api/5.2/info_quickstart.html)
- Previews should be typed, with a generic file viewer as fallback: rendered Markdown/HTML/PDF, plots, image/canvas, 3D model, and diagram each need different navigation and comparison controls. That follows from the concrete viewers and comparison tools above. — [JupyterLab layout types](https://jupyterlab.readthedocs.io/en/stable/user/interface_customization.html); [Posit Quarto](https://docs.posit.co/ide/user/ide/guide/documents/quarto-project.html); [Figma compare](https://help.figma.com/hc/en-us/articles/15023193382935-Compare-changes-in-Dev-Mode)
- If Relay offers both textual and direct-manipulation editing, it should define which representation is authoritative and what survives regeneration. draw.io's documented style-preserved/geometry-lost behavior is a concrete warning against implying seamless round trips. — [draw.io editable Mermaid](https://www.drawio.com/blog/mermaid-updates/)

### Gaps
- These sources do not show a mature universal cross-application preview protocol for a terminal IDE. Blender, Onshape, Figma, Jupyter, and Mermaid each expose different artifact models and lifecycle boundaries. — [Blender editors](https://docs.blender.org/manual/en/latest/editors/index.html); [Onshape Feature Studios](https://cad.onshape.com/help/Content/FeatureStudio/feature_studios.htm); [JupyterLab layout types](https://jupyterlab.readthedocs.io/en/stable/user/interface_customization.html)
- The draw.io July 2026 article conflicts with its older manual; an implementation decision would need testing against the current editor before assuming shape/source round trips. — [New announcement](https://www.drawio.com/blog/mermaid-updates/); [Older manual](https://www.drawio.com/docs/manual/insert/insert-mermaid/)

## What architecture and conflict-handling patterns should Relay evaluate?

### Takeaway
Relay should separate shared-workspace observation from edit ownership, and make conflicts and preview freshness visible. The evidence favors layered capabilities: filesystem observation, reviewable deltas, isolated agent runs where collision risk is high, and artifact-specific views connected to a source revision.

### Cited Findings
- Zed uses Git worktrees to isolate threads that may touch the same files, and its Git UI highlights merge-conflict regions with Use current, Use incoming, or Use Both controls. Cursor offers an agent-assisted Resolve in Chat action, followed by review and application of the proposal. — [Zed Parallel Agents](https://zed.dev/docs/ai/parallel-agents); [Zed Git](https://zed.dev/docs/git); [Cursor Git](https://docs.cursor.com/en/more/ai-commit-message)
- VS Code's current agent review flow has distinct integration actions for folder sessions, worktree sessions, and cloud sessions. It explicitly says that reverting a chat checkpoint does not reverse terminal commands, network actions, deployments, or external-service changes. — [VS Code review](https://code.visualstudio.com/docs/agents/run/review-code-edits)
- Zed's file-panel undo can fail if another program changes the filesystem state, and it notifies the user; its remote-development docs say the local UI holds unsaved changes, while remote projects can reconnect and restore them. — [Zed Project Panel](https://zed.dev/docs/project-panel); [Zed remote development](https://zed.dev/docs/remote-development)
- Replit's isolated background-task flow includes an explicit Ready-to-apply boundary, a preview and test log, and automatic conflict handling at application time. Figma's branch merge presents spatial before/after review and conflicts but currently cannot selectively merge individual changes. — [Replit task board](https://docs.replit.com/features/agent/task-board); [Figma branch merge](https://help.figma.com/hc/en-us/articles/5691189138839-Merge-branch-into-main-file)
- Aider's watch mode treats a *saved source comment* as an instruction trigger; its Git workflow commits preexisting dirty edits separately before agent edits. Cursor's checkpoints deliberately exclude manual edits. These represent different provenance policies despite similar “agent beside editor” appearances. — [Aider watch mode](https://aider.chat/docs/usage/watch.html); [Aider Git](https://aider.chat/docs/git.html); [Cursor checkpoints](https://docs.cursor.com/en/agent/chat/checkpoints)

### Inferences
- A feasible Relay sequence is: (1) show files and renderable outputs linked to the terminal's current working directory; (2) watch disk changes and record hashes/mtime plus any known initiating agent/tool; (3) provide a diff/review pane that still includes terminal-only changes; (4) add worktree-backed agent sessions and explicit apply/merge when parallel edits become common. This sequence combines observed review blind spots with the isolation patterns in Zed, VS Code, and Replit. — [VS Code review](https://code.visualstudio.com/docs/agents/run/review-code-edits); [Zed Parallel Agents](https://zed.dev/docs/ai/parallel-agents); [Replit task board](https://docs.replit.com/features/agent/task-board)
- For an open file with unsaved manual edits, Relay should avoid silently replacing its buffer on disk changes: hold the buffer, detect that disk diverged from the last loaded version, and offer compare/reload/merge or save-as. This is a design proposal, motivated by Zed's documented failure of undo after external mutations and the absence of a universal concurrent-buffer guarantee in the cited systems. — [Zed Project Panel](https://zed.dev/docs/project-panel); [Zed remote development](https://zed.dev/docs/remote-development)
- A preview should indicate **live, stale, rendering, or failed**, and identify the source path/revision and process that produced it. Quarto preview changes on re-render, Onshape applies FeatureScript at Commit, and Figma Make updates after an agent prompt, so “file changed” and “rendered result changed” are separate events. — [Posit Quarto](https://docs.posit.co/ide/user/ide/guide/documents/quarto-project.html); [Onshape Feature Studios](https://cad.onshape.com/help/Content/FeatureStudio/feature_studios.htm); [Figma Make](https://help.figma.com/hc/en-us/articles/42009840449175-Edit-a-Figma-Make-file)
- Relay's panes could be a persistent layout of terminal/agent thread, file editor, change review, and selected artifact preview, with saved workspace layouts and a way to reopen running processes. JupyterLab and Krita demonstrate saved layout state, while JupyterLab separately tracks running terminals/kernels. — [JupyterLab interface](https://jupyterlab.readthedocs.io/en/stable/user/interface.html); [JupyterLab running panel](https://jupyterlab.readthedocs.io/en/stable/user/running.html); [Krita workspaces](https://docs.krita.org/en/reference_manual/resource_management/resource_workspace.html)

### Gaps
- No cited primary source specifies a complete cross-editor algorithm for merging unsaved human buffer edits with agent disk writes. Relay would need to design and test this directly, including rename/delete races and non-text files. — [Zed Project Panel](https://zed.dev/docs/project-panel); [VS Code review](https://code.visualstudio.com/docs/agents/run/review-code-edits)
- The sources do not establish whether existing tools expose a standardized event stream that identifies *which* process changed a file when the agent used a terminal command. VS Code explicitly omits terminal-only changes from its agent change list. — [VS Code review](https://code.visualstudio.com/docs/agents/run/review-code-edits)
- No source here measures user outcomes or performance cost for persistent file watching, 3D/image previews, or worktree application. Those require Relay prototypes and empirical testing. — [Zed worktrees](https://zed.dev/docs/ai/parallel-agents); [Blender editors](https://docs.blender.org/manual/en/latest/editors/index.html); [Replit task board](https://docs.replit.com/features/agent/task-board)
