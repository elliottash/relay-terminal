### Inferences

- **Recommendation:** reuse Tests as a compact overview with known checks and a separate findings list; reuse history navigation, Stop, and card attachment. Do not encode “the model suspects a bug” as a failing deterministic test.
- **Recommendation:** introduce an attack-run record and a finding record. Minimum run fields: target revision/snapshot, scope, method and version, model/prompt version, environment, budget, start/end/outcome, artifact references. Minimum finding fields: stable identity, claimed failure, location, evidence/reproducer, validation state, reviewer disposition, related card. This extends the existing evidence store rather than requiring a new general agent engine.
- **Recommendation:** confirmed, repeatable failures can become ordinary checks and enter the existing signal lifecycle. Unconfirmed model findings should remain advisory; otherwise the existing auto-repair path could act on speculation.

## Does Relay already have scheduling, isolated attacks, and security or multi-agent review?

### Takeaway
Relay has background jobs and generic multi-agent execution, but neither is a durable attack scheduler or a destructive-execution sandbox. The card's `security-review`/`ultra` claim conflates potentially available external harness features with an integrated, verified Relay capability.

### Cited Findings

- **Verified: jobs are live conversation-owned subprocesses.** `JobTable` keeps at most eight running jobs, retains bounded output, provides stop/output operations, and starts separate process groups. Jobs end when their conversation/subagent/worker ends. The code contains no durable recurring schedule in this module. ### Inferences

- **Recommendation:** first pilot can use an explicit, bounded generic reviewer over a frozen diff with existing agent controls. A scheduler is unnecessary for evaluating that pilot.
- **Missing for recurring operation:** persisted schedule/trigger, missed-run behavior, concurrency arbitration across projects, spending/time budgets, retention, cancellation after restart, and stable snapshot selection. Reusing background jobs supplies execution and stop controls, not these semantics.
- **Missing for active mutation/chaos:** disposable source/data copies, explicit network policy, stripped/allowlisted environment, resource limits, artifact export, cleanup, and proof the original workspace was not modified. This is a prerequisite for the proposed methods, not a suggestion to run them now.
- **Recommendation:** separate investigator from fixer. Existing signal agents have a repair mandate; an attacker should first preserve its reproducer and produce evidence. Otherwise the discovered defect and evidence can disappear into the agent's edits.

### Gaps

- No verified installed security-review skill or ultra cloud-review route; generic model/provider support is the only confirmed local implementation.
- No durable recurring attack scheduler was located by targeted searches of `backend/relay_core` and `src`; UI timers and signal pickup should not be described as one.
- No filesystem/network containment guarantee was found in the inspected isolation, jobs, test environment, or subagent paths. Guest harnesses may apply their own permissions; those vary and were not audited here.
