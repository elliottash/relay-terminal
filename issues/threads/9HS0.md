Four decisions before this becomes cards (report §4):

1. Approvals on the Start pane. #K2FV says one screen, before anything else, that cannot be dismissed without choosing. Recommendation: keep the explicit pick but put it as the last row of the Start pane, so a newcomer reads one screen, not two stacked at 400 and 800 ms. Alternative: the Start pane opens after the approvals screen.
2. Which starter tasks ship bundled. Recommendation: all eleven in the report, with "Triage my email" and "Organize multiple subscriptions" shipping as recipes that say "needs a skill" and offer the skills dialog until a bundled skill exists.
3. Does picking a starter task file it as the first Board card? Recommendation: yes when the folder already has a Board; otherwise the recipe runs without one and the project-init question is asked only when the person opens the Board.
4. Does the Start pane carry the switchboard material? #8E4Q permits it for a surface seen once. Recommendation: typography and the two destination colours only, no materials, until #8E4Q is decided.

Follow-up decisions before the three delivery cards are written, each with a recommendation. Numbered from 5 to continue the card's list.

5. Esc versus the approvals pick. #K2FV says the approvals screen cannot be dismissed without choosing, and the Start pane's footer offers Esc to skip. Recommendation: Esc on the Start pane collapses the starter tasks and leaves only the three sentences and two buttons; the pane closes on the pick, and "Allow everything — recommended" is focused so the expert path is Esc, Enter. The cautious set stays in force until then, as today.

6. Order when a task is picked before the approvals row is answered. Recommendation: Enter on a task asks the approvals row first ("one thing first"), then stages the prompt. A first task that raises approval cards on every edit is the wrong first impression, and the owner's rule that the pick is explicit holds either way.

7. Which folder a recipe runs in. Relay from the app menu starts in the home directory, and Open project uses a native folder dialog with no way to create one. Recommendation: a recipe that needs a folder shows a folder row with two choices, "Choose a folder…" (the existing dialog) and "Make one for me" that creates ~/Relay/<task name>/, which doubles as the disposable sandbox the research asks for; "Just give me a terminal" uses the cwd.

8. "Generate some art" on a keyless install. Relay Free's roles are main, flash and lite; no image role is documented. Recommendation: the recipe ships and says "needs a provider that makes images" on Relay Free, unless the gateway adds an image role, which is an ops decision outside this card.

9. Keybinding preset and theme rows. Presets exist (Relay, Warp, VS Code, Konsole) and the theme picker exists. Recommendation: one row for keys ("Keys: Relay · Warp · VS Code · Konsole", Relay preselected), no theme row (follow the system; Options › Appearance has it). Cursor's import and Linear's light/dark question are the precedents; the keys row is the expert-facing one.

10. Persona question. The literature suggests asking "how comfortable are you with terminals?". Recommendation: none; the starter tasks are the segmentation, and the hints toggle is one row in Options.

11. Tip budget for a newcomer. Existing limits are 3 shows per id, 10-minute cooldown, 20-second global gap, 30-minute cooldown for idle tips. Recommendation: keep those and add a per-session cap of 5 behaviour-triggered tips and a quiet period of 2 minutes after a recipe's first Enter, so the first task is not narrated over.

12. The "Options › Security can ask before deletions" tip after an agent's first rm or git push under allow-everything. It sits next to #K2FV's recommendation of allow-everything. Recommendation: keep it, once ever, phrased as information ("Relay can ask first for deletions, moves and pushes: Options › Security"), not as advice.

13. Relay Free first-reply note. Recommendation: once ever, on the first agent reply of the install, plus the 20% tip; not once per day.

14. Import row when Claude Code, Codex or Warp files exist. Recommendation: the row shows what it found ("3 instruction files, 2 keys") and the starter relay.md is still written silently when nothing is imported, keeping #ZYRB's behaviour.

15. First-run health check. Nothing in-app checks that the bundled Python backend and a shell are present; installed-smoke.py covers CI only. Recommendation: in scope for card 1 as one line at the top of the Start pane when something is missing ("Relay's helper could not start: …"), nothing when all is well.

16. Measurement stays local. Recommendation: no network reporting of any kind; the activation counter is a local file the QA drive reads. If an opt-in "share anonymous first-run counts" toggle is ever wanted, it is its own card.

17. Windows and macOS. Recommendation: recipes are platform-aware where a path or program differs (the Downloads folder, ssh on Windows), and the first delivery is verified on Linux under Xvfb with the other two platforms as follow-ups on the card.

18. The name. Recommendation: "Start" for the pane, /start for the command, "Show the Start pane" in Options › General and the Actions palette.

19. Filing. Recommendation: once these are answered, file the three delivery cards from report §5 as planned cards linked here, so panes can claim them.
