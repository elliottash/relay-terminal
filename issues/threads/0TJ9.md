Storage format — my answer to "is this in plain text? should we use sqlite or another compressed solution?": **plain text, no sqlite.**

- The caps already bound it: 5,000 lines / 512 KiB per session, newest kept, written only on the way out (quit, window close, pane/tab close), never per keystroke — and it is a fraction of the pane's own 20,000-line engine scrollback.
- The writer is the GUI (`Pane::saveScrollback` at close). `conv_index` is the *worker's* sqlite cache and the GUI cannot reach it: the text there would need a new protocol message and would not exist when no worker is running — and sqlite buys nothing, because the text is only ever looked up by id.
- Precedent: session files are plain JSON, uncompressed, usually far larger than the text; `state/scrollback/<id>.txt` is already plain text.
- Escape hatch if size ever bites: wrap the same single file in Qt's `qCompress` (zlib) behind `writeScrollback`/`readScrollback` — no new dependency, no schema, several-fold on terminal text, a 1-byte magic prefix keeps old plain files readable. I would do that only if the store shows up in a size problem; sqlite I would not do at all.

Three things to settle before building (recommendations in bold):
1. **Plain text now**, qCompress later if size ever bites. Say "compressed" and the file is a qCompress blob from the start.
2. **Rewind's auxiliary file.** Terminal text is not turn-tagged and a chat rewind unprints nothing (the pane keeps showing the dropped turns; `rewound` only prints a line). Recommended: on each conversation rewind snapshot the pane's current text to `<id>.scrollback.rewound-<turn>.txt` (same caps, never replayed, deleted with the conversation), while the live file keeps being what the pane shows and what a resume replays. The alternative — text exactly up to turn N — needs a snapshot at every turn's end (more files, more writes).
3. **Guests: `state/scrollback/guest-<source>-<id>.txt`** in Relay's own directory, because a guest pane has no `session_dir` and Relay should not write inside `~/.claude` / `~/.codex`, which the guests prune themselves. The alternative is a sidecar beside the guest's own transcript: exactly where the conversation is, but Relay's file inside another program's directory.

Say "go" and I take all three recommendations as written.
