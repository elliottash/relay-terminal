**A real bug, and not this card's to fix: `relay_core/conv_index.py` shares one sqlite connection between threads with no lock.** One run in 48 died with `sqlite3.InterfaceError: bad parameter or other API misuse` inside `ConversationIndex.search` (`conv_index.py:1732`, through `session_protocol._conversations_event`). The connection is opened `check_same_thread=False` (`conv_index.py:754` and `:779`) and there is no mutex anywhere in the module, while `session_protocol._conversations` runs `guest_sessions.reconcile(self.index())` on a thread of its own against the same connection as the listing that scheduled it. That error is what SQLite says when two threads use one connection at once; `check_same_thread=False` turns off the check, not the requirement. It wants a lock around every use of `self._db` — not only `_run` — which is a change to a central module in the guest-sessions work (GT7X) and deserves its own card rather than a hunk in this one.
